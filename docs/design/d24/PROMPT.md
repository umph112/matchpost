그다음 D24-OPEN-BUNDLE.md 대로 만들어줘. 인플루언서 오픈 상세 화면이야.

[왜 만드나]
「여수 1박 2일」처럼 며칠짜리 오픈 하나에 딜시트가 여러 개 붙는데,
지금은 그것들이 흩어져 있어서 「그날 몇 시에 어디를 가고 총 얼마를 받나」를 볼 곳이 없어.

[선행 조건은 이미 있어 — 내가 검색해서 확인했어]
  proposals.schedule_id  → 묶는 기준. 날짜 겹침으로 묶지 마, 다른 오픈 건이 섞여
  proposals.start_at · duration_min (0029)
  set_proposal_time() + 겹침 검사 (0054)

[없는 것 — 0090 으로 추가 (검색해서 0건 확인했어)]
  proposal_stops   한 건에 방문지 여러 곳
  proposals.perk   제공받는 것
  proposals.is_stay 숙박 여부

  ⚠️ schedules.fee 를 금액으로 쓰지 마. text 「30만원~」이고 오픈의 희망 페이야.
    실제 금액은 proposals.budget.

[핵심 규칙 다섯]

① 한 건에 방문지가 여러 곳일 수 있어
   꼬북 두 지점 묶어 10만원, 박람회장·돌산 묶어 50만원 — 실제 일정이야.
   방문마다 proposal 을 나누면 한 건이 두 건으로 세어지고 금액이 두 번 잡혀.

② 시간대는 협의 시각에서 파생돼
   방문 1곳 = −1시간 ~ +2시간 (총 3시간)
   방문 여러 곳 = 첫 방문 −1시간 ~ 마지막 방문 +2시간
     (방문마다 3시간을 따로 잡으면 16:00·17:00 연속 방문이 겹쳐)
   숙박 = 20:00 → 익일 10:00

③ 숙박은 빈 시간 계산에서 빼
   자는 시간이라 다른 일정과 겹쳐도 돼. 같이 계산하면 저녁 이후가 통째로 막혀서
   「하나 더 받을 수 있는 시간」이 사라져.
   그리고 숙박 협찬은 두 덩어리야 — 낮에 잠시 들러 촬영하고 저녁에 다시 가서 자.
   촬영 블록(1시간 30분)은 빈 시간을 차지하고, 돈 줄은 반복하지 마
   (「같은 건이에요 — 조건과 정산은 숙박 카드에 있어요」).

④ 보수는 세 가지야 — 원고료만 / 제공만 / 둘 다
   제공만인 건에 「0원」이라 쓰지 마. 손해 본 건으로 읽혀.
   제공만인 건에 「결제일 미정」도 붙이지 마 — 정할 결제일이 남은 걸로 읽혀서
   인플루언서가 협의하러 가. 「결제 없음」이야.
   제공 표현은 인플루언서가 고칠 수 있게 파란 점선 밑줄. 금액은 못 고쳐.

⑤ 위치는 간략히 · 빈 값이 정상
   정확한 주소를 안 받아. 이동 시간도 계산 안 해 —
   직선거리 근사는 해안·산지에서 크게 틀리고, 틀린 안내는 없느니만 못해.
   그래도 적게 하는 이유는 다른 광고주가 대시했을 때의 판단 근거라서야.
   ⚠️ 모르는 걸 추정해 채우지 마. 본인 일정을 보면서 틀린 정보를 읽게 돼.

[레이아웃에서 놓치기 쉬운 것]
  · 돈 줄의 모든 항목에 flex-shrink:0 · white-space:nowrap.
    하나라도 줄어들면 트랙이 꽉 찰 때 「100,000 / 원」으로 숫자가 쪼개져
  · 「협업 N건」은 실제 건수. 파생 블록(촬영)을 세면 부제와 합이 어긋나
  · 빈 칸을 반드시 그려. 빈 칸이 보여야 「여기에 하나 더」가 보여. 30분 미만은 빼고
  · 합계 옆 「각각 입금됩니다」가 없으면 한 번에 들어오는 돈으로 읽혀
  · 「받을 순서」 헤더가 「결제 예정일 순」이면 실제로 정렬해. 미정은 뒤로
  · 제목의 「1박 2일」은 날짜에서 파생. 손으로 적으면 어긋나
