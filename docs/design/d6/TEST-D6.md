# D6 테스트 기록

프로토타입을 직접 눌러 확인하며 찾은 결함과 수정 내용.
**A ~ C 는 레포에도 같은 결함이 있을 수 있으니 확인하세요.**
D 는 프로토타입만의 문제라 레포에 반영할 것이 없습니다.

---

## A. 흐름이 끊겨 있던 것 (기능 없음)

| 화면 | 무엇이 없었나 | 어떻게 고쳤나 |
| --- | --- | --- |
| 양쪽 콘솔 | 신고를 넣는 입구가 아예 없었다. 관리자에는 신고 접수 화면과 제재 사다리가 다 있는데 처리할 것이 도착할 길이 없었다 | 대화 헤더에 "문제 신고" 신설. 유형은 관리자 REPORT_TYPES 를 역할별로 자름 |
| 광고주 정산 | **미수 상태가 없었다.** 예정일이 지난 건이 인플루언서 화면과 관리자 모니터에만 뜨고 정작 돈 낼 사람 화면엔 없었다 | 예정 / 미수 / 완료 3탭. KPI 2번 칸을 미수로 |
| 광고주 정산 | "정산 완료로 기록"이 모달만 닫고 아무것도 안 바뀌었다 | 카드가 실제로 완료로 이동. 미수 -1, 완료 +1, KPI 동시 |
| 광고주 대시 | 취소 요청을 받은 쪽에 **수락 버튼이 없었다.** 양쪽 안내문은 "상대가 수락해야 확정됩니다"라고 말하는데 그 버튼이 없었다 | 확정 바에 "취소 요청 수락" 추가 |
| 광고주 대시 | 취소를 수락해도 딜시트는 진행중 그대로였다 | 취소가 딜시트 행 · 파생 숫자 · 대화 목록 배지까지 전파 |
| 대시 보내기 | 날짜를 글로만 적어서 딜시트가 읽을 수 없었다 | 날짜 선택 UI. 오픈일이 기본, "다른 날짜 제안"으로 변경 |
| 인플루언서 대시 | 날짜를 변경하면 진행일이 "협의중"으로 남아 수락 버튼이 영원히 비활성이었다 (막다른 길) | 합의된 날짜가 곧바로 진행일이 된다 |
| 관리자 회원 | **승인 버튼이 없었다.** "서류 보기"와 "재요청"만 있었다 | 승인 버튼 + "승인하면 가입 축하금 20,000C 지급" 안내 |
| 관리자 제재 | "단계 올리기"가 글자만 바꾸고 사다리는 그대로였다 | 실제로 표시 -> 제한으로 올라가고 다음 단계도 갱신 |
| 캠페인 등록 | "등록하기"가 목록으로 돌아가기만 했다. 캠페인이 생기지 않았다 | 실제로 생성되고 크레딧이 기록된다 |
| 인트로 | "인플루언서로 가입하기"가 아무 일도 하지 않았다 | QR 안내 모달을 연다 |
| 인플루언서 대시 | 미수 카드에서 문의할 길이 없었다 | "대시에서 문의하기" - 기존 대화로 이동 + 문구 프리필 |

## B. 값이 갈려 있던 것 (원본이 여럿)

| 무엇 | 어떻게 갈렸나 | 어떻게 고쳤나 |
| --- | --- | --- |
| **"오늘"** | 인플루언서 · 관리자는 8/2, 광고주만 7/28. 같은 미수 건이 D+8 과 D+13 으로 갈렸다 | 세 콘솔 통일. 달력의 달 · 상단바 기간 · D-day 를 전부 파생 |
| 미수 건 | 인플루언서 300,000 / 광고주 900,000 5명 / 관리자 900,000 으로 제각각 | 같은 이름 · 금액 · 예정일로 통일 |
| 관리자 미수 | 광고주별 미수 건수 · 금액이 미수 목록과 무관하게 하드코딩. 목록에 없는 광고주가 미수 2건, 목록에 있는 광고주는 0건 | 목록에서 파생 |
| 크레딧 값 | 같은 항목이 화면마다 3,000 / 1,000 / 500 | 단일 카탈로그(POLICY)에서 파생. 8개 파일 수정 |
| 인플루언서 매출 | 홈 화면과 매출 화면이 다른 배열을 읽고 있었다 | SALES 하나로 통합 |
| 딜시트 기한 | 게재 열이 캠페인 기본값을 전원에게 적용 | 사람별 값이 있으면 그것을 쓰고 "(변경)" 표시 |
| 공통 일정 스트립 | D-day 가 마크업에 하드코딩되어 오늘이 바뀌어도 그대로 | CP_DUE 에서 파생 |
| 온보딩 · 크레딧 안내 | 가입 축하금이 30,000 인데 정책은 20,000/10,000 | 정책값으로 통일. 베타 무료 표기 추가 |

## C. 계산이 틀렸던 것

| 무엇 | 증상 | 원인 |
| --- | --- | --- |
| 단계 인덱스 | 수정/컨펌을 끄면 그 단계에 있던 사람이 **이미 끝낸 앞 단계로 되돌아갔다** (게재 -> 원고) | `slice(0, i+1)` 이 자기 자신까지 세었다. `slice(0, i)` 로 수정 |
| 진행바 분모 | 보류자가 분모에 있어 영원히 100% 가 안 되었다 | 정산 대상 인원(보류 제외)으로 변경 |
| "가장 빠른 정산일" | 배열 순서를 믿어 8/20 을 가리켰다 (실제 8/10) | D-day 로 정렬 |
| 평균 지연 | "지연 없음"인데 "평균 4일 지연"이 같이 떴다 | 지연 0건이면 평균을 표시하지 않는다 |
| 세무자료 요청 | 전역 플래그라 한 캠페인에서 보내면 전부 "보냄"으로 보였다 | 캠페인별로 저장 |
| 취소 후 집계 | 취소된 사람이 확정 인원 · 집행 금액 · 팔로워 합계에 그대로 남았다 | LIVE 배열에서 파생 |
| 달력 | 달이 7월에 멈춰 있어 8월 2일이 7월 칸에 칠해졌다 | TODAY 에서 달과 첫 요일을 파생 |

## D. 프로토타입만의 문제 (레포에 반영할 것 없음)

- 모바일 6화면 죽은 탭 전수 점검 (더보기 · 계정 · 기타 행)
- 일정 등록 모달에서 선택 시 페이지가 사라지던 문제
- 링크 오연결 20여 건 (보고서 미리보기, 미입력 필터, 친구 프로필 등)
- 로고의 점 표기 통일 (문자 -> 실제 원, 세로 중앙, 좌우 같은 여백)
- safe-area 여백 (아이폰 홈 인디케이터가 탭바를 가림)
- 모바일 웹 홈 화면 추가 안내 배너

## 확인 방법

첨부한 프로토타입을 열어 아래 순서로 눌러보면 위 흐름을 그대로 볼 수 있습니다.

**취소 전파**
1. 광고주 PC -> 대시 -> 개인 대화 -> 여행자 민준
2. "취소 요청 수락"
3. 캠페인 -> 성수 델리카페 신메뉴 방문 리뷰 -> 딜시트
4. 민준 행이 "취소 · 사유"로 바뀌고 헤더 숫자가 줄었는지 확인

**날짜 제안**
1. 광고주 PC -> 인플루언서 찾기 -> 아무 결과의 "대시하기"
2. "다른 날짜 제안" 선택 -> 날짜 비운 채로 "대시 보내기" (안 눌려야 정상)
3. 날짜 입력 후 보내기 -> 대화에 카드가 생기는지 확인

**진행 과정 조립**
1. 광고주 PC -> 캠페인 등록
2. "수정/컨펌" 칩 클릭 -> 게재뒤수정이 자동으로 켜지고 8단계가 되는지
3. "게재뒤수정"도 클릭 -> 6단계, 안내문이 "가이드대로 게재하면 끝나요"로 바뀌는지

**정산**
1. 광고주 PC -> 정산 -> 미수 탭
2. 세무자료 요청 -> 그 캠페인만 "요청 보냄"이 되는지
3. 대상 인원 보기 -> 세무자료 수령으로 변경 -> "정산 완료로 기록"
4. 완료 탭으로 이동하고 KPI 가 같이 바뀌는지
