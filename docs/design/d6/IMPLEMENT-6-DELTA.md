# A. 대시 (대화)

## A1. 대화는 두 종류이고, 모양으로 구분한다

```
src/app/(dashboard)/advertiser/messages/page.tsx
src/components/messages/ConversationRow.tsx
```

- 광고주는 두 종류를 갖는다: **캠페인 대화**(1:N)와 **개인 대화**(1:1)
- 인플루언서는 한 종류만 갖는다: 전부 1:1
- 목록에서 **아바타 모양으로** 구분한다
  - 캠페인 대화: `border-radius:10px` 사각, 배경 `#DBEAFE`, 글자 `#1D4ED8`
  - 개인 대화: `border-radius:50%` 원, 배경 `#FEF3C7`, 글자 `#B45309`
- 방 헤더에 배지를 둔다: 개인 `1:1`, 캠페인 `1:N 참여 N명`

## A2. 캠페인 대화의 상대 말풍선에 보낸 사람 이름

```
src/components/messages/MessageBubble.tsx
```

- 캠페인 대화에서 **상대 말풍선 위에** 아바타(20px 원) + 이름을 붙인다
- 개인 대화에는 붙이지 않는다 (상대가 한 명뿐이라 시끄럽다)
- 데이터: 메시지에 `from` (보낸 인플루언서 이름) 필드 필요

## A3. 캠페인 대화방 참여자 목록과 개별 발송

```
src/app/(dashboard)/advertiser/messages/[id]/page.tsx
```

- 방 상단 안내문 아래에 참여자 칩 목록을 둔다 (아바타 22px + 이름)
- 칩을 누르면 **확인 모달**: "OOO님에게만 보낼까요?"
  - 본문: "캠페인 참여자 전체가 아니라 OOO님에게만 메시지가 전달됩니다. 다른 참여자는 이 내용을 볼 수 없어요."
  - 보조: "조건이 한 사람만 달라지면 딜시트도 그 사람만 바뀝니다."
  - 버튼: 취소 / 확인(파랑 `#1D4ED8`)
- 확인하면 입력창 위에 파란 배너가 **계속** 표시된다
  - "OOO님에게만 보냅니다 - 다른 참여자에게는 가지 않아요" + "전체로 되돌리기"
- 그 상태로 보낸 메시지는 `only: 이름` 을 함께 저장한다
- 저장된 메시지는 말풍선 위에 배지로 남는다: "OOO님에게만" + "다른 참여자에게는 가지 않았어요"
- 개별 발송 말풍선 배경은 `#1D4ED8` (일반 발송은 `#17171B`)

## A4. 인플루언서 쪽 단체 발송 표시

```
src/app/(dashboard)/influencer/messages/[id]/page.tsx
```

- 광고주가 캠페인 대화에서 보낸 말은 인플루언서의 1:1 창으로 도착한다
- 그 말풍선 위에 배지: "단체 발송" + "참여자 모두에게 같은 내용이 갔어요"
- 말풍선 배경 `#EFF6FF`, 테두리 `#DBEAFE`, 글자 `#1E3A8A`
- 대화 헤더 부제: "OO - 광고주와 나만 볼 수 있어요"

## A5. 대화마다 담당자 한 명

```
src/app/(dashboard)/advertiser/messages/[id]/page.tsx
src/lib/permissions.ts (신규)
```

- 각 대화에 `managerId` 를 둔다
- 담당자가 아닌 팀 구성원은 **그 대화에 관여할 수 없다** (입력창 비활성)
- 예외는 **소유자(owner)** 뿐
- 소유자가 담당자 아닌 대화에 들어오면 입력창 위에 노란 배너:
  "OOO 담당 대화예요. 대표로 보내면 「회사 대표 대리 발송」으로 표시됩니다."
- 소유자가 보낸 말은 `proxy: true` 로 저장하고, 양쪽 화면 말풍선 위에 배지:
  "회사 대표 대리 발송" (배경 `#FEF3C7`, 글자 `#92400E`)
- 대화 헤더에 "담당 OOO" 배지

## A6. 날짜 제안은 값으로 보낸다

```
src/app/(dashboard)/advertiser/search/page.tsx
src/components/dash/SendDashModal.tsx
```

- 대시 보내기 모달에 **날짜 선택**을 넣는다 (글로 쓰지 않는다)
- 상대가 오픈을 열어뒀으면 그 날짜들이 기본 선택지로 뜬다 (칩)
- 마지막 칩은 "다른 날짜 제안" - 고르면 `<input type="date">` 가 열린다
- 오픈이 없는 상대(친구 등)에게도 날짜 질문은 나온다
- **날짜가 비면 「대시 보내기」가 비활성**된다 (배경 `#EAEAEE`, 글자 `#B0B0BB`)
  안내문도 바뀐다: "날짜를 골라야 보낼 수 있어요 - 이 값이 딜시트의 진행일이 됩니다."
- 「다시 보내기」모드에는 날짜 질문이 없다
- 보내면 대화에 **말풍선이 아니라 카드**로 남는다
  - 라벨 "날짜 제안", 날짜 크게, 부제 "열어두신 날짜예요" 또는 "열어두신 날짜와 다른 날이에요"
  - 꼬리말 "상대가 수락하면 이 날짜로 확정돼요"
  - 배경 `#FFFBEB`, 테두리 `#FDE68A`

## A7. 날짜 제안의 수락과 되제안

```
src/app/(dashboard)/influencer/messages/[id]/page.tsx
```

- **상대가 보낸** 제안 카드에만 수락 버튼이 있다 (자기 제안은 자기가 확정 못 한다)
- 수락하면 그 날짜가 협업의 진행일이 되고, 카드가 "확정됨"으로 바뀐다
- 되제안: 다른 날짜를 골라 카드를 다시 보낸다. 원래 제안은 "다른 날짜로 답함"으로 표시
- **날짜 변경은 양쪽 수락을 초기화하지 않는다** (이미 합의한 것을 두 번 시키지 않는다)
- 합의된 날짜는 곧바로 진행일이 된다. "협의중" 으로 남기지 않는다

## A8. 취소는 딜시트까지 간다

```
src/app/(dashboard)/advertiser/messages/[id]/page.tsx
src/app/(dashboard)/advertiser/campaigns/[id]/dealsheet/page.tsx
```

- 상대가 취소를 요청하면 확정 바에 **「취소 요청 수락」** 버튼이 나온다
- 수락하면 `cancelledParticipants[name] = 사유` 를 기록한다
- 딜시트가 그 값을 읽어 해당 행을 바꾼다
  - 배지 "취소" + 사유
  - 단계 "진행 없음", 기한/방문/게재/메모 전부 비움
  - 페이 `-`, 세무자료 `-`, 정산 "해당 없음"
  - 행을 **지우지 않는다** (기록이다)
- 취소된 사람은 **모든 파생 숫자에서 빠진다**
  - 모집 확정, 집행 확정, 팔로워 합계, 게재 수, 딜시트 탭 카운트, 대시보드 KPI
- 대화 목록 배지도 "취소 확정"으로 바뀐다

## A9. 캠페인 맥락이 있는 알림은 새 대화를 만들지 않는다

```
src/app/(dashboard)/influencer/settlements/page.tsx
```

- 미수 카드의 액션은 신고가 아니라 **「대시에서 문의하기」**
- 누르면 그 캠페인을 함께 진행한 **기존 대화**로 이동하고, 입력창에 문구를 채운다
  "결제 예정일이 지났는데 확인 부탁드립니다."
- 자동 지연 알림은 그 대화 안에 **시스템 줄**로만 남는다 (말풍선 아님)

# B. 캠페인과 딜시트

## B1. 진행 과정은 조립식이다

```
src/app/(dashboard)/advertiser/campaigns/new/page.tsx
src/lib/campaign-stages.ts (신규)
```

전체 단계 (9개):
```
협의, 수락, 가이드, 방문, 원고, 수정/컨펌, 게재, 게재뒤수정, 정산
```

켜고 끄는 규칙:

| 단계 | 규칙 |
| --- | --- |
| 방문 | 캠페인 구분이 "지역"일 때만 자동으로 켜진다 |
| 원고 | 사전 컨펌에 딸린다. 수정/컨펌을 끄면 함께 빠진다 |
| 수정/컨펌 | 광고주가 켜고 끈다. 끄면 게재뒤수정이 자동으로 켜진다 |
| 게재뒤수정 | 광고주가 켜고 끈다. 단독으로 끌 수 있다 |
| 나머지 | 항상 켜짐 |

- 등록 화면에 칩으로 보여준다. 켜고 끌 수 있는 칩은 노란색(`#FFFBEB`/`#F59E0B`), 고정은 흰색, 꺼진 것은 회색(`#FAFAFB`/`#C4C4CE`)
- 칩 옆 힌트: 방문은 "지역 자동"/"지역 아님", 원고는 "사전 원고 없음", 나머지는 "켜짐"/"꺼짐"
- 아래 한 줄 안내가 조합에 따라 바뀐다
  - 둘 다 켜짐: "원고를 받아 컨펌한 뒤 게재하고, 게재 후에도 수정을 요청할 수 있어요."
  - 사전 컨펌만: "원고를 미리 받아 컨펌한 뒤 게재해요."
  - 게재뒤수정만: "원고 없이 먼저 게재하고, 게재 후에 수정을 요청해요."
  - 둘 다 꺼짐: "가이드대로 게재하면 끝나요 - 수정 단계가 없으니 가이드를 자세히 적어주세요."

## B2. 기본 일정 + 사람별 변경

```
src/app/(dashboard)/advertiser/campaigns/new/page.tsx
src/app/(dashboard)/advertiser/campaigns/[id]/dealsheet/page.tsx
```

- 캠페인 등록 때 **기본 일정**을 정한다: 원고 마감, 수정/컨펌 마감, 게재 마감, 수정 요청 마감, 정산 예정일
- 켜져 있는 단계의 기한만 묻는다 (수정/컨펌을 끄면 그 칸이 사라진다)
- **방문일에서 기한을 자동 파생하지 않는다** (방문일이 달라도 게재를 같은 날로 묶고 싶은 광고주가 있다)
- 대시에서 협의해 **그 사람만** 바뀐 경우에만 개별 값이 기본을 덮는다
- 개별 값이 적용된 칸은 **"(변경)"** 을 붙이고 파란색(`#1D4ED8`)으로 표시한다

## B3. 뺀 단계에 있던 사람 처리

```
src/lib/campaign-stages.ts
```

- 단계를 끄면 그 단계에 머물던 사람은 **다음 살아 있는 단계**로 읽는다
- 인덱스 계산 시 **자기 자신은 세지 않는다**
  ```
  const drop = ALL_STAGES.slice(0, i).filter(s => OFF.has(s)).length;
  return clamp(i - drop, 0, activeStages.length - 1);
  ```
  `slice(0, i+1)` 로 하면 이미 끝낸 앞 단계로 되돌아간다 (실제로 발생한 버그)

## B4. 확정 인원이 생기면 단계 구성 잠금

```
src/app/(dashboard)/advertiser/campaigns/[id]/edit/page.tsx
```

- 확정 인원이 1명이라도 있으면 진행 과정 구성을 바꿀 수 없다
- 바꿔야 하면 취소 후 재등록

# C. 정산

## C1. 광고주 정산에 미수 상태

```
src/app/(dashboard)/advertiser/settlements/page.tsx
```

- 탭을 **예정 / 미수 / 완료** 3개로 한다
- 미수 = 지급 예정일이 지났는데 기록되지 않은 건
- 미수 탭이 0건이 아니면 탭 자체를 빨강으로 (`#FEF2F2`/`#DC2626`)
- KPI 두 번째 칸을 "가장 가까운 정산일"에서 **"미수"** 로 바꾼다
  - 값: 미수 총액 (없으면 "없음"), 부제: "N건 · 가장 오래 D+N" 또는 "예정일을 지킨 상태예요"
- 미수 카드 안에 빨간 안내:
  "예정일 M/D 에서 N일 지났어요. 매일 1회 지연 알림이 발송되고 있고(누적 N회), 이 기록이 이용 제한 판정에 쓰입니다. 결제 예정일 변경이 필요하면 캠페인 대화창에서 참여 인플루언서에게 공지하고 결제일 변경을 확정하세요."

## C2. 정산 기록이 실제로 상태를 옮긴다

```
src/app/(dashboard)/advertiser/settlements/page.tsx
```

- 「정산 완료로 기록」을 누르면 확인 모달 뒤 **카드가 완료 탭으로 이동**한다
- 미수 -1, 완료 +1, KPI 동시 반영
- 모달만 닫히고 아무것도 안 바뀌면 기록됐는지 알 수 없다

## C3. 세무자료 요청은 캠페인별

```
src/app/(dashboard)/advertiser/settlements/page.tsx
```

- 「요청 보냄 · 대기」 상태를 **캠페인마다 따로** 저장한다
- 전역 플래그로 두면 한 캠페인에서 보내고 다른 캠페인도 보낸 것처럼 보인다

## C4. 진행바 분모는 정산 대상 인원

```
src/app/(dashboard)/advertiser/settlements/page.tsx
```

- "N / M명" 의 M 은 **보류자를 뺀 인원**
- 보류자를 넣으면 영원히 100% 가 안 된다

## C5. 지연 알림 매일 1회

```
src/lib/notifications.ts
src/app/api/cron/settlement-reminder/route.ts (신규)
```

- 지급 예정일이 지나고 기록이 없으면 광고주에게 **매일 1회** 알림
- 누적 횟수를 저장한다. 이 값이 제재 판정 근거가 된다
- 양쪽이 대화에서 예정일 변경에 합의하면 지연이 아니므로 발송이 멈춘다
- 대화에는 시스템 줄로 남는다: "8월 2일 · 지연 알림 발송 (2회) · 3일째부터 운영팀이 함께 확인합니다"

## C6. 세 화면의 미수 값이 같아야 한다

```
src/lib/settlements.ts
```

- 같은 미수 건이 인플루언서 화면, 광고주 화면, 관리자 모니터에 **같은 이름 / 금액 / 예정일 / D+** 로 나와야 한다
- 관리자의 광고주별 미수 건수와 금액은 **미수 목록에서 파생**시킨다. 따로 적으면 어긋난다
- 지연이 0건이면 "평균 N일 지연"을 쓰지 않는다

## C7. 세 콘솔의 "오늘"은 하나

```
src/lib/date.ts
```

- 광고주 / 인플루언서 / 관리자가 같은 기준 날짜를 쓴다
- 달력의 달, 상단바 기간, D-day 를 전부 이 값에서 파생시킨다
- 프로토타입에서 광고주만 다른 날짜를 써서 같은 건이 D+8 과 D+13 으로 갈렸다

```ts
  { key: 'open_create',       label: '오픈 등록',             dir: 'charge', amount:  1000, status: 'beta_free' },
];
```

- 화면 어디서도 금액을 직접 쓰지 않는다. 전부 이 배열에서 읽는다
- 프로토타입에서 같은 항목이 화면마다 3,000 / 1,000 / 500 으로 갈려 있었다

## D2. 크레딧을 쓰는 유일한 경로

```
src/lib/credits.ts (신규)
```

```ts
charge(userId, actionKey) -> LedgerEntry
```

- 모든 지급과 차감이 이 함수를 지난다. 함수 밖에서 잔액을 건드리지 않는다
- `status === 'beta_free'` 면 **0 을 기록하되 원래 값을 함께 남긴다**
  - 원장 표시: "무료 (베타)" + 회색 "원래 500C"
  - 합계 표시: "6회 · 25,000 사용 · 무료 1건"
- 베타 무료는 값을 0 으로 만드는 것이 아니라 **청구만 끄는 것**이다

## D3. 원장

```
src/app/(dashboard)/[role]/credits/page.tsx
```

- 누가 언제 왜 받고 썼는지 전부 기록한다
- 지금 잔액이 왜 그 숫자인지 추적 가능해야 한다

## D4. 유료화는 구독과 이용권만 (중요)

```
결제 화면을 만들 때
```

- **금액 충전 UI 를 만들지 않는다** ("10,000원 = 10,000C" 방식 금지)
- 유료화는 **구독**(월정액, 기능 포함 수량)과 **이용권**(횟수 단위)으로만
- 크레딧은 활동 보상으로 **지급만** 하고 직접 판매하지 않는다
- 이유: 선불전자지급수단에 해당하면 전자금융업 등록 대상이 되고, 자본금 요건이 크다

## D5. 정책 변경 규칙


- 값 변경은 **시행 30일 전 공지 + 유예 기간** 후 시행
- **시행일 이후 발생 건에만** 적용. 진행 중인 협업에 소급하지 않는다
- 변경 이력(누가, 언제, 얼마에서 얼마로)을 남긴다

- 유형은 관리자 REPORT_TYPES 를 역할별로 잘라 쓴다
  - 광고주: 원고 미제출 · 게재 지연 / 가이드 불이행 / 무단 불참 / 욕설 · 부적절한 요구 / 기타
  - 인플루언서: 대금 미지급 / 일방적 취소 · 조건 변경 / 가이드와 다른 요구 / 욕설 · 부적절한 요구 / 기타
- **유형 + 설명 둘 다 필수**. 하나라도 비면 접수 버튼 비활성
- 접수하면 대화에 남고 버튼이 "신고 접수됨"으로 바뀐다
- 모달 첫 줄: "매치포스트는 판정하지 않습니다 - 양쪽 기록을 확인하고 안내합니다. 접수되면 상대에게도 같은 내용이 전달되고, 처리 결과는 알림함으로 보내드립니다. 더 하실 말씀은 고객센터로 남겨주세요."
- 흐름: **접수 = 대화 / 결과 = 알림함 / 추가 문의 = 고객센터**
- 피신고자는 신고를 닫을 수 없다

## F1. 사업자 정보 표시

```
src/app/(marketing)/layout.tsx

```

전자상거래법 제10조에 따라 **초기 화면**(로그인 전 인트로) 하단에 표시:

```
상호 | 대표 | 사업자등록번호 | 통신판매업 신고번호 | 주소 | 고객센터 | 이메일 | 개인정보 책임자 | 호스팅
```

- **개인정보처리방침** 링크는 다른 링크보다 **굵게**
- **「사업자정보 확인」** 을 따로 둔다 (시행규칙 제7조 2항)
- **통신판매중개자 면책 문구**를 함께 둔다:
  "매치포스트는 광고주와 인플루언서를 잇는 통신판매중개자이며, 통신판매의 당사자가 아닙니다. 협업 조건 · 대금 지급 · 콘텐츠 게재의 이행 책임은 각 거래 당사자에게 있습니다."
- 콘솔(로그인 후)에는 사업자 정보를 넣지 않는다. 대신 사이드바 맨 아래에 약관 / 개인정보처리방침 링크만
