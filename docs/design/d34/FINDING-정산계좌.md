# findings 추가 — 인플루언서 정산 계좌를 받는 곳이 없다

D34 설정 화면 작업 중 확인. **폭 문제가 아니라 없는 기능이다.**
프롬프트3 지시대로 이번에 만들지 않고 기록만 한다.

## 무엇이 없나

| 있어야 할 것 | 실제 |
|---|---|
| 인플루언서가 계좌를 입력하는 폼 | 없음 |
| 계좌를 담는 DB 컬럼 | 없음 |
| 광고주가 송금할 곳을 확인하는 화면 | 없음 |

## 실측

```
src 안에서 「계좌」가 나오는 파일 — 2개, 둘 다 문서다
  src/app/privacy/page.tsx:113
  src/app/terms/page.tsx:234
  (influencer/profile/page.tsx:311 은 이번에 적은 주석이다)

sql/migrations/*.sql 105개 전수 — bank | 계좌 | 예금주 | account_number  → 0건
```

## 왜 문제인가

정산 규칙은 **「광고주가 직접 송금하고 매치포스트는 기록만 한다」** 이다.
그런데 광고주가 어디로 보낼지 알 방법이 제품 안에 없다.

약관·개인정보처리방침은 계좌를 **대시(메시지) 첨부파일**로 주고받는 것을 전제한다:

> 첨부파일에 담긴 개인정보(주소 · 연락처 · 신분 서류 · **계좌 사본** 등)는
> 회사의 데이터베이스에 별도로 저장되지 않으며, 파일이 삭제되면 함께 사라집니다.
> — terms/page.tsx:234 · privacy/page.tsx:113

즉 지금은 계좌가 대시에서 말·사진으로 오가고 있을 가능성이 크고,
파일이 지워지면 근거도 같이 사라진다. 딜시트가 조건을 구조화한 것과 어긋난다.

## 이번에 만들지 않는 이유 (사용자 지시)

계좌는 개인정보라 **어디에 두는지부터** 정해야 한다 —
`user_private` 에 넣을지, 암호화할지, 양쪽 확정 후에만 광고주에게 보일지.
그 결정은 사용자가 별도 문서로 준다.
