# VS Code 프롬프트 2 (D34) — 검색 마무리 · 설정

아래 블록을 그대로 복사해 붙여넣으세요.

---

```
검색 잘 됐어. order 대신 col-start/row-start 를 쓴 판단이 맞아 —
order 는 탭 순서와 눈에 보이는 순서를 어긋나게 해.
추천 절을 안 넣은 것도 맞아. 데이터 소스가 없으면 빈 절을 만들지 않아.

[① 광고주 필터] 넣지 마. 대신 좌측에 「분야」를 옮겨줘.

  광고주로 캠페인을 찾는 일은 드물고, 브랜드명(campaigns.brand_name)과
  회사명(advertiser_public 뷰)이 두 자리에 있어 쿼리가 복잡해져.

  좌측이 비어 보이는 건 다른 이유야 — 좁히는 조건이 좌우로 갈려 있어:

    좌 380px   지역 + 분야          ← 좁히는 조건
    우 나머지   날짜 + 키워드 + 검색  ← 날짜가 주 조건

  날짜가 이 화면의 주 조건이라 우측 위가 맞고,
  지역·분야는 성격이 같아 함께 두면 좌측이 채워져.

  ⚠️ 모바일 순서는 지금 그대로 둬 — 날짜 → 시/구·동 → 키워드 → 분야 → 검색.
     PC 에서만 분야가 좌측으로 가면 돼 (col-start/row-start 로).

[② 모바일 3가지] 셋 다 그대로 둬. 되돌리지 마.
  · 부제 — 기간 캠페인 규칙은 모바일에서도 알아야 해
  · 「카테고리」 → 「분야」 — 용어 통일은 프로젝트 규칙이고, 이 화면만 달랐던 게 결함이야
  · 빈 상태 — 모바일에서도 빈 화면이 뜨면 안 돼

[③ 7열 달력] 별건으로 둬.
  광고주 검색에는 이미 있어(D11 2단계). 나중에 같은 것을 인플루언서 검색에도 붙이면 돼.
  지금 <input type="date"> 로도 검색은 되니까.

[그다음 — 설정] D34 문서 1절이야.

  지금 입력칸이 전부 1100px 로 늘어나 세로 1900px 로 쌓여.
  전화번호 한 칸이 1100px 인 게 모바일 폼을 늘린 증거야.

  · 탭 3개로 나눠줘 — 프로필·채널 / 정산 계좌 / 크레딧.
    그것만으로 세로 1900px 이 사라져
  · ⚠️ 탭마다 그리드가 달라. 하나로 통일하지 마 —
      프로필   minmax(0,1fr) minmax(0,1fr)
      정산계좌 minmax(0,1fr) 320px
      크레딧   300px minmax(0,1fr)   ← 좌측이 검정 잔액 카드
    이유가 있어: 프로필은 두 덩어리가 대등, 정산은 계좌가 주·안내가 보조,
    크레딧은 잔액이 먼저 눈에 들어와야 해
  · 입력칸은 카드 폭(약 580px)에 맞춰. 짧은 값(휴대폰·팔로워 수)은 카드 안에서 2열
  · 카드 헤더 높이를 고정하지 마 — padding + align-items:center (프로젝트 규칙).
    제목 아래 설명줄이 붙으면 고정 높이에서 위로 쏠려
  · 저장은 SaveButton(D31 [4]) 그대로
  · ⚠️ 상단바 별명·아바타는 「기본 정보」와 항상 같은 값이어야 해 (아바타 = initialOf(별명))
  · 탭 3개는 모바일에도 적용해줘 — 한 화면에 다 넣으면 모바일에서도 1900px 이야

  ⚠️ 정산 계좌·크레딧 탭에 넣을 내용이 지금 이 화면에 없으면 알려줘.
     다른 화면(/credits 등)에 있으면 옮기지 말고 링크만 두는 게 맞을 수도 있어 —
     그건 판단이 필요하니 멈추고 물어봐.

①② 먼저 고치고 커밋, 그다음 설정으로 가줘.
끝나면 두 폭 캡처와 grep 결과를 알려줘.
```
