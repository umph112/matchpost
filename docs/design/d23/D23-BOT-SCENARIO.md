# D23 — 봇 시나리오 (가입부터 협업 끝까지)

세 계정(관리자 · 광고주 · 인플루언서)으로 실제 가입해서 **협업 하나를 처음부터 완료까지**
끌고 갑니다. Playwright 로 실행합니다.

> ⚠️ 이 폴더의 문서는 전달받은 원본이 인코딩이 깨진 채로 도착해서 내용 기준으로 옮겨 적은 것입니다.

---

# 0. 준비

실데이터가 아직 없고 테스트 후 전부 지울 예정이라 격리는 신경 쓰지 않습니다.

| 항목 | 방법 |
| --- | --- |
| 이메일 인증 · 알림톡 | **건너뜁니다.** Supabase 에서 계정을 `confirmed` 로 만들어 시작하거나 환경변수로 우회. 이 두 경로는 사람이 따로 확인합니다 |
| 계정 이메일 | `bot+adv@matchpost.kr` 등 — 나중에 한 번에 지우기 쉽게만 |
| 사업자번호 | 체크섬을 통과하는 실제 형식 번호. **중복 검사가 있으니 매 실행마다 다른 값** |
| 정리 | 실행 도중 지우거나, 다 끝나고 전체를 비움 |

이 봇의 목적은 **사람이 빼먹는 것을 잡는 것**입니다. 화면 하나하나를 손으로 누르면
어디를 안 봤는지 알 수 없습니다. 그래서 아래 시나리오를 **빠짐없이 순서대로** 도는 것이
격리보다 중요합니다.

---

# 1. 핵심 원칙 — 「눌렀다」가 아니라 「값이 바뀌었다」

지금까지 찾은 결함이 대부분 이 자리였습니다 — **모달은 닫히는데 아무것도 안 바뀌는 것들.**

각 단계에서 **하기 전 숫자를 읽고, 하고 난 뒤 다시 읽어 비교**하세요.

```
before = KPI 읽기
하기
after  = KPI 읽기
assert(after.미수 === before.미수 - 1)
```

버튼 존재 여부만 확인하는 테스트는 이 결함을 못 잡습니다.

# 2. 시나리오 — 협업 하나의 전 과정

## 단계 1. 광고주 가입

```
/ → 「광고주」 탭 → 대표 이메일 · 로그인 아이디 체크박스 · 대표 이름/휴대폰
   → 암호 · 사업자번호 · 사업자등록증 파일 → 팀 초대(건너뛰기) → 완료
```

확인:
- [ ] `/pending` 에 **실제로 도달** (파일명 오타로 404 나던 자리)
- [ ] 완료 화면의 가입 축하금이 `creditConfig` 값과 같음 (하드코딩 아님)
- [ ] 사업자번호 중복 검사 → 같은 번호로 두 번째 가입 시 409 + 마스킹된 소유자 이메일

## 단계 2. 관리자 승인

```
관리자 로그인 → /admin/users → 승인 대기 → 「승인」
```

확인:
- [ ] **확인 대기 −1 · 승인 +1** 동시 반영
- [ ] 승인 즉시 **서류 원본 삭제** (처리방침에 공개한 내용)
- [ ] 광고주에게 가입 축하금이 실제로 지급됨 → 크레딧 원장에 행이 생김

## 단계 3. 인플루언서 가입 + 오픈 등록

```
/signup → 인플루언서 → (PC 면 QR 모달) → 모바일 폭으로 진행
  이메일 → 이름/활동명/휴대폰 → 채널 인증 · 분야 1+2 · 지역 → 완료
→ /influencer/schedule → 날짜 선택 → 오픈 등록 (홀 · 지역 · 한 줄 소개)
```

확인:
- [ ] PC 에서 인플루언서를 고르면 **QR 모달**이 뜸 (그냥 폼이 열리면 실패)
- [ ] 오픈 등록 후 **크레딧 원장에 「무료 (베타)」 행 + 원래 금액**이 남음
- [ ] 오픈이 광고주 검색에 **날짜 단위로** 나타남

> ⚠️ D28 2번에서 QR 게이트를 제거했습니다. 이 항목은 이제 **「PC 에서도 폼이 열린다」**가
> 정답입니다. 위 체크박스는 문서 원문이며, 실행 시 반전해서 봅니다.

## 단계 4. 대화 보내기

```
광고주 → /advertiser/search → 날짜 달력에서 그 날 선택 → 결과 카드 → 「대화하기」
  → 날짜 선택 (오픈일 기본 / 「다른 날짜 제안」) → 「대화 보내기」
```

확인:
- [ ] 「다른 날짜 제안」 고르고 **날짜를 비우면 버튼이 비활성** (필수 · 눌러도 안 닫힘)
- [ ] 보낸 뒤 대화에 **날짜 카드**가 생김 (말풍선이 아님)
- [ ] 카드에 「오픈해두신 날짜예요」 또는 「…다른 날이었어요」
- [ ] 내가 보낸 카드에는 **수락 버튼이 없음**
- [ ] 크레딧 원장에 대화 발송 행

## 단계 5. 인플루언서 수락 → 협업 성립

```
인플루언서 → /influencer/messages → 그 대화 → 날짜 카드 「이 날짜로 수락」
→ 조건 확인 → 「협업 수락」
```

확인:
- [ ] 수락 후 카드가 **「확정됨 · 딜시트에 반영」**
- [ ] **연락처가 그때 공개됨** (성립 전에는 어디서도 안 보여야 함)
- [ ] 딜시트가 생성되고 그 사람 행이 있음
- [ ] 양쪽 「협업 성사」 크레딧 지급

## 단계 6. 진행 — 가이드 → 방문 → 원고 → 검수

```
광고주 딜시트에서 단계 진행 · 대화로 가이드 파일 전송
인플루언서 검수 링크 입력
```

확인:
- [ ] 단계 배지가 실제로 움직임
- [ ] 첨부파일에 **만료 예정일**이 표시됨 (7일)
- [ ] 인플루언서 대시보드에 **다음 할 일 하나**가 크게

## 단계 7. 일정 변경 협의 (진행일 · 결제일)

```
한쪽이 「일정 변경 제안」 → 상대 수락
```

확인:
- [ ] **진행일** 제안 카드에 「진행일 제안」 라벨
- [ ] **결제일** 제안 카드에 「결제일 제안」 라벨 (D20)
- [ ] 결제일 수락 후 **매출 예정이 그 날짜로 이동** → 인플루언서 매출 화면에서 순서가 바뀜
- [ ] **지연 알림 카운터가 0으로 리셋** (합의된 변경은 지연이 아님)
- [ ] 양쪽 수락이 **초기화되지 않음** (같은 합의를 두 번 시키지 않음)

## 단계 8. 정산

```
광고주 → /advertiser/settlements → 그 캠페인 → 세무자료 요청 → 「정산 완료로 기록」
인플루언서 → /influencer/earnings → 「입금 확인」
```

확인:
- [ ] 세무자료 「요청 보냄」이 **그 캠페인만** (다른 캠페인은 그대로)
- [ ] 세무자료 미수령이면 기록 버튼이 **「세무자료 N명 요청하기」**로 바뀜
- [ ] 기록 후 **카드가 완료 탭으로 이동** · 미수 −1 · 완료 +1 · KPI 동시
- [ ] 기록자 이름이 남음 (`campaigns.settled_by`)
- [ ] **팀원 계정으로도 이 기록이 가능** (대표 전용이 아님)
- [ ] 인플루언서 입금 확인 후 **미수에서 빠짐**

## 단계 9. 상호 평가

```
양쪽 「평가 남기기」 → 별점 · 태그 · 코멘트
```

확인:
- [ ] 한쪽만 했을 때 **상대 평가가 안 보임** (블라인드)
- [ ] 양쪽 다 하면 공개
- [ ] 광고주 공개 프로필(`/advertiser/[id]`)의 평가 평균·건수가 **갱신됨**

# 3. 가장 중요한 검사 — 세 화면의 같은 값

**사람이 눈으로 하기 가장 힘들고, 봇이 가장 잘 잡는 것입니다.**

미수 건 하나를 만들어(정산 예정일을 과거로) 세 곳에서 읽고 비교하세요:

| 화면 | 읽을 것 |
| --- | --- |
| 인플루언서 `/influencer/earnings` | 회사명 · 금액 · 예정일 · D+ · 지연 알림 횟수 |
| 광고주 `/advertiser/settlements` 미수 탭 | 캠페인 · 금액 · 예정일 · D+ |
| 관리자 `/admin/settlements` 미수 목록 | 광고주 · 금액 · 예정일 · D+ · 알림 횟수 |

```
assert(inf.amount === adv.amount === admin.amount)
assert(inf.dday   === adv.dday   === admin.dday)
```

전에 같은 건이 300,000 / 900,000 / 900,000 으로 갈려 있었습니다.
그리고 「오늘」이 읽을 때마다 달라 D+8 과 D+13 으로 갈렸습니다.

**추가로 대조할 값:**
- 딜시트 헤더의 모집 확정 · 진행 확정 · 프로 합계가 **행 수의 합과 일치**
- 회사 관리 모드 「전체」가 **팀원별 합과 정확히 일치**
- 크레딧 잔액이 **원장 합과 일치**

# 4. 회귀 검사 — 지금까지 고친 것들

한 번 고친 것이 다시 깨지는지 봅니다. **값 비교로** 하세요.

| 검사 | 무엇이 깨졌었나 |
| --- | --- |
| 취소 요청 수락 → 딜시트 행이 「취소」로, 확정 인원 −1 | 대화만 취소되고 딜시트는 진행중이었음 |
| 진행 과정에서 「원고/컨펌」 끄기 → 그 단계 사람이 **다음** 단계로 | 이미 끝난 전 단계로 되돌아갔음 |
| 팀원 화면 전환 → KPI 4칸이 **함께** 바뀜 | 라벨만 바뀌고 숫자는 그대로였음 |
| 캠페인 대화에서 참여자 한 명 지정 → 확인 표시 → 「○○님에게만」 배지 | — |
| 이관 확인 → 그 건이 내 목록에 「이관」 꼬리표로 | — |
| 정산 진행바 분모가 **보류자 제외** 인지 | 보류자가 들어가 100% 가 안 됐음 |
| 모달 두 개 겹칠 때 대화 보내기가 항상 위 (z-200) | 전부 z-50 이라 순서가 무작위였음 |
