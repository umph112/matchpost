# 봇 E2E 점검 계획 — 전 기능

목적: **사람이 막히는 곳을 봇이 먼저 찾는다.** 통과가 목적이 아니라 막히는 지점을 찾는 것이다.

> ⚠️ 이 폴더의 문서는 전달받은 원본이 인코딩이 깨진 채로 도착해서 내용 기준으로 옮겨 적은 것입니다.
> 표·순서·항목은 원본 그대로지만 문장 표현이 원본과 다를 수 있습니다.

---

# 0. 원칙

| 원칙 | 뜻 |
| --- | --- |
| **우회하지 않는다** | 봇이 막히면 거기서 멈추고 기록한다. DB를 직접 고쳐 통과시키면 사람은 여전히 막힌다 |
| **아무 일도 안 일어나면 결함이다** | 버튼을 눌렀는데 화면이 그대로면 실패로 읽는다 (D28 4번이 그것이었다) |
| **두 역할이 번갈아 움직인다** | 대화·협의·취소는 한쪽만으로 되지 않는다. 계정을 갈아타며 진행한다 |
| **배치는 수동 실행** | 크론을 기다리지 않는다. `POST /api/admin/batch/…` + `CRON_SECRET` |
| **앞이 막히면 뒤를 건너뛰지 않는다** | 의존 관계를 지킨다. 데이터가 없으면 뒤 시나리오가 거짓 통과한다 |

## 계정

| 계정 | 용도 |
| --- | --- |
| `adv-a` | 광고주 대표 (캠페인 · 정산 · 팀) |
| `adv-a-member` | `adv-a` 의 팀원 (초대 링크로 가입) |
| `adv-b` | 두 번째 광고주 (사업자번호 중복 · 대상 대비 확인) |
| `inf-a` | 인플루언서 (전 과정) |
| `inf-b` | 두 번째 인플루언서 (오픈 묶음 · 취소) |
| 관리자 | **기존 계정 사용. 새로 만들지 않는다** |

⚠️ 사업자번호는 **체크섬을 통과하는 실제 형식**이어야 합니다 (`isValidBizNo`).
아무 숫자나 넣으면 1단계에서 막힙니다.

# S3. 대화 — 두 역할이 번갈아

**여기가 가장 중요합니다.** 매치포스트의 핵심이고 상태가 얽혀 있습니다.

| # | 누가 | 무엇 |
| --- | --- | --- |
| 3-1 | `adv-a` | 오픈을 보고 대화 → **날짜 선택 필수** · 크레딧 차감 기록 |
| 3-2 | `inf-a` | 받은 대화 확인 · 조건 확인 |
| 3-3 | `inf-a` | 진행일 제안 → `adv-a` 수락 → 딜시트 반영 |
| 3-4 | `adv-a` | 협의 수락 → `inf-a` 수락 → **양쪽 확정 · 연락처 공개** |
| 3-5 | `adv-a` | **결제일 변경 제안** → `inf-a` 수락 → 매출 예정 이동 · 지연 카운터 리셋 |
| 3-6 | `adv-a` | 캠페인 대화에서 개별 발송 (`inf-a` 지정) → 확인 모달 → 「○○님에게만」 |
| 3-7 | `inf-a` | 그 말이 「단체 발송」이 아니라 개별로 보이는지 |
| 3-8 | `inf-b` | **취소 요청** → `adv-a` 수락 → 딜시트 정리 (배지 · 인원 감소 · 금액 감소) |
| 3-9 | `inf-b` | 취소 카운트가 올라감 → **철회하면 되돌아오는지** (D27 0093) |

⚠️ 3-4 에서 **연락처가 확정 전에 보이면 결함**입니다.

# S10. 배치 13개 · 수동 실행

각각 `POST` + `Authorization: Bearer $CRON_SECRET` 로 부르고 **응답과 부수효과**를 확인합니다.

```
blog-analytics · purge-attachments · dormant-decay · comeback
payment-reminders · settlement-reminder · trust-score-recalc
visit-weekly · visit-monthly
report-autoclose · sanction-recalc
cancellation-autoconfirm · cancellation-count-reset
```

⚠️ `purge-attachments` 는 **7일 지난 첨부를 지웁니다.** 테스트 데이터에 새 첨부만 있으면
0건이 정상입니다. 지우려고 날짜를 조작하지 마세요.

# 실행 순서

```
S0 가입  →  S1 캠페인 · S2 오픈  →  S3 대화  →  S4 딜시트  →  S5 정산
                                       ↓
                        S6 팀 · S7 크레딧 · S8 신고 (S3 데이터 필요)
                                       ↓
                             S9 관리자 · S10 배치 (전체 데이터 필요)
                                       ↓
                              S11 모바일 · S12 공개 페이지
```

**S3 이 병목입니다.** 대화가 안 되면 S4~S8 이 전부 거짓 통과합니다.

S13 은 **모든 시나리오에 병행**합니다. 화면을 열 때마다 13-1 의 네 가지를 함께 봅니다.

# 보고 형식

각 항목마다 세 줄:
```
S3-4  양쪽 확정            통과 / 막힘
      막힌 이유 (화면·버튼·에러)
      사람도 같은 곳에서 막히는가 — 예 / 아니오
```

마지막 줄이 중요합니다. **봇만 막히는 것과 사람도 막히는 것은 다릅니다.**

막다른 길은 따로 모아주세요:
```
[막다른 길]
  화면              뭐가 없나    빠져나올 다음 행동
  /influencer/…     없음         없음
```

직관성도 따로:
```
[직관성]
  다음 행동이 안 보임    2곳 (인플루언서 홈 · 크레딧)
  같은 값 두 번 입력     2곳 (활동명 · 분야)
  숫자 불일치            1곳 (대화 배지 3 / 목록 2건)
  캠페인 등록 완료까지    7클릭
```

⚠️ **한 시나리오가 끝날 때마다 보고하세요.** 전부 끝난 뒤 한 번에 주면
앞 시나리오의 막힘이 뒤로 번진 것을 구분할 수 없습니다.
