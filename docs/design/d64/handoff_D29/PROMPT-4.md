# VS Code 프롬프트 4 (D29) — 단계별 담당자

아래 블록을 그대로 복사해 붙여넣으세요.

---

```
서버액션 잘 됐어. 세 개로 한정한 것 · 영향 행 수를 센 것 · 실패 시 낙관적 갱신을
안 한 것 · DB 를 원복한 것 다 맞아. 커밋해줘.

[① 인플루언서 단계 이동 — 열어줘. 내 설계가 틀렸어]

  「인플루언서는 조작 없음」이라고 정한 게 잘못이었어.
  「원고 제출」·「게재 완료」는 인플루언서가 하는 일인데,
  지금 구조면 광고주가 대신 눌러주기를 기다려야 해.

  다만 전부 열지 마 — 단계마다 누가 넘기는지가 달라:

    단계          누가
    협의          광고주
    수락          광고주
    가이드        광고주   (가이드를 주는 쪽)
    방문          인플루언서
    원고          인플루언서
    수정/컨펌     광고주   (확인하는 쪽)
    게재          인플루언서
    게재뒤수정    광고주   (확인하는 쪽)
    정산          광고주   (돈 보내는 쪽)

  · 자기 차례인 단계에서만 「→」 버튼이 보이게
  · 자기 차례가 아니면 버튼 없이 「상대가 확인하면 넘어가요」 정도로
    (지금 무엇을 기다리는지 보여야 해 — 버튼만 없으면 멈춘 것처럼 보여)
  · 서버액션에도 같은 규칙을 넣어. 화면에서만 막으면 뚫려 —
    advanceStage 가 「그 단계의 담당자인가」를 확인하고 아니면 거절해야 해

  세무자료 토글 — 인플루언서에게도 열어줘 (제출하는 쪽이야)
  정산 기록 — 광고주만 (지금 그대로)
  복사 재등록 · 서로 등록 · 행 체크박스 — 광고주만 (지금 그대로)

  ⚠️ 단계 담당자 표를 코드 한 곳에 두고 화면·액션이 같이 읽게 해줘.
     두 곳에 적으면 어긋나.

[② 캠페인 「가이드」 — 그대로 둬]

  진행 중인 건의 단계 배열이 통째로 바뀌는 건 위험해. 네 판단이 맞아.
  computeEnabledStages 가 가이드를 못 내놓는 건 별건으로 두고,
  그때 「기존 건은 그대로 · 신규 캠페인만 9단계」로 처리할게.
  이번엔 오픈만 ALL_STAGES 로 둔 상태를 유지해줘.

[확인해서 알려줘]
  · 인플루언서 세션에서 「원고」 단계를 넘길 수 있나 (DB 에 남나)
  · 인플루언서가 「수락」 단계를 넘기려 하면 액션이 거절하나
  · 광고주가 「원고」 단계를 넘기려 하면 거절하나
  · 자기 차례가 아닐 때 화면에 무엇을 기다리는지 보이나
```
