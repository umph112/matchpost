# VS Code 프롬프트 3 (D29) — 버튼 라벨 두 줄 접힘

아래 블록을 그대로 복사해 붙여넣으세요.

---

```
봇이 도는 화면에서 버튼 글자가 두 줄로 접히는 게 보였어. 전수로 잡아줘.

[원인]
  버튼에 white-space: nowrap 이 없으면 폭이 좁아질 때 라벨이 접혀.
  「대시에서 / 문의하기」처럼 갈라지면 버튼으로 안 읽히고, 높이가 늘어 옆 버튼과 어긋나.

[고칠 것]
  버튼·링크 라벨은 접히지 않게 해줘:
    · <button> 과 버튼처럼 쓰는 <a>·<div> 에 whitespace-nowrap
    · 폭이 부족하면 접는 게 아니라 padding 을 줄이거나 라벨을 짧게
    · 두 줄이 필요한 만큼 긴 라벨이면 그 라벨이 잘못된 거야 — 짧게 고쳐줘

  찾는 방법:
    grep -rn "<button" src/app src/components | grep -v "whitespace-nowrap" | wc -l
    그다음 실제로 짧은 폭에서 접히는 것만 골라. 전부에 붙일 필요는 없어 —
    긴 문장을 담는 버튼(빈 상태의 안내형 버튼)은 접히는 게 맞을 수도 있어

[특히 볼 곳]
  · 카드 안 액션 버튼 — 카드가 좁아지면 제일 먼저 접혀
    (미수 카드 「대시에서 문의하기」 · 딜시트 행 액션 · 정산 카드)
  · 나란히 놓인 버튼 두 개 — 하나만 접히면 높이가 어긋나
    (모달 푸터의 취소/확인 · 「딜시트 보기」+「이관 확인」)
  · 표 안의 버튼 — 열 폭이 고정이라 접히기 쉬워
  · 모바일 폭(390px)에서 다시 확인 — PC 에서 안 접혀도 거기서 접혀

[함께 볼 것]
  버튼이 아니라 배지·칩도 같아. 「양쪽 확정」 「취소 요청 잦음」처럼 상태를 말하는 것이
  두 줄이 되면 상태로 안 읽혀. 배지에도 whitespace-nowrap 을 줘.

[찾은 것 둘] 「결제일 변경 제안」 버튼 — 이건 줄이기 어려워

  라벨을 「결제일 변경」으로 줄일 수 있지만, 「제안」이 빠지면
  바로 바뀌는 것처럼 읽혀. 상대가 수락해야 바뀌는 거라 그 말이 필요해.

  → 두 줄로 두고 모양을 맞춰줘:

    · line-height 를 좁게 — leading-[1.3]
    · 상하 padding 을 같게 (py-2.5 처럼 한 값으로. pt/pb 를 다르게 주지 마)
    · text-center — 두 줄이 가운데 정렬돼야 버튼으로 읽혀
    · 줄바꿈 위치를 정해줘: 「결제일 변경」 / 「제안」 (「결제일」/「변경 제안」 아님)
      <br className="…" /> 대신 white-space 를 두 어절로 끊는 방식이 안전해
    · ⚠️ 옆에 다른 버튼이 있으면 부모에 items-stretch — 한쪽만 두 줄이면 높이가 어긋나

  [두 줄 버튼 공통 규칙 — 다른 곳에도 적용]
    두 줄이 필요한 버튼은 있어. 접히는 게 문제가 아니라 **정렬이 안 맞는 것**이 문제야.
    두 줄로 둘 때는 위 네 가지(좁은 행간 · 균등 padding · 가운데 정렬 · 형제와 높이 맞춤)를
    반드시 함께 줘. 하나만 빠져도 어긋나 보여.

[하지 말 것]
  ⚠️ 모든 텍스트에 nowrap 을 뿌리지 마. 문장은 접혀야 해 —
    안내문·설명·빈 상태 문구는 그대로 둬.
  ⚠️ nowrap 을 주면서 overflow 를 안 다루면 글자가 밖으로 삐져나가.
    필요하면 min-w-0 + truncate 를 함께.

[찾은 것 하나] 「협업 제안」이 들어간 버튼이 두 줄로 나와.
  그런데 용어도 틀렸어 — 프로젝트 용어는 「대시」야. 「제안」이 아니야.

  grep -rn "협업 제안\|협업제안" src

  라벨을 이렇게 고쳐줘:
    「이 날짜로 협업 제안」  →  「이 날짜로 대시」
    「협업 제안하기」        →  「대시 보내기」
    「협업 제안」            →  「대시 보내기」

  짧아져서 한 줄에 들어가고, 용어도 맞아. 두 문제가 한 번에 풀려.

  ⚠️ 「제안」이 다른 곳에도 남아 있을 거야 — 함께 봐줘:
    grep -rn "제안" src/app src/components | grep -v "날짜 제안\|결제일 제안\|진행일 제안"
    (「날짜 제안」·「결제일 제안」·「진행일 제안」은 맞는 표현이야. 그건 그대로 둬 —
     대시가 아니라 날짜를 제안하는 거니까)

지금 하던 작업(D29 서버액션)을 먼저 끝내고, 그다음에 이걸 해줘.
끝나면 어느 버튼들을 고쳤는지 목록으로 알려줘.
```
