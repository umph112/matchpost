## 화면 11. 정산 (`/advertiser/settlements`)  신규

딜시트의 일괄 정산 바가 **한 캠페인 안**을 본다면, 이 화면은 **캠페인을 가로질러** 본다.
"이번 달에 얼마가 나가고, 무엇이 막혀 있나"를 한 번에 확인하는 자리다.

[주의] **매치포스트는 송금을 대행하지 않는다.** 실제 지급은 광고주가 직접 한다.
그래서 주 버튼도 "지급하기"가 아니라 **"정산 완료로 기록"** 이다  -  이 문구를 바꾸면
플랫폼이 돈을 다루는 것처럼 오해를 사고, 사고가 났을 때 책임 소재가 우리로 온다.
우측 레일 맨 위에 이 사실을 amber 박스로 **항상 노출**한다.
[주의] 정산 단위는 **캠페인**이다. 개인별 지급 버튼을 만들지 않는다.

### 요약 4칸
정산 예정(합계 + 캠페인 수) / 가장 가까운 정산일(+D-day) / **세무자료 미비 N명**(빨강) / 정산 완료(누적)
점 색: amber  /  blue  /  red  /  green (전 화면 공통 규칙)

### 탭 + 캠페인 카드
탭 `예정 / 보류 / 완료` + 건수.

카드(패딩 `16px 20px`, `gap:13px`)
- 1행: 캠페인명 `14.5px/800` + 상태 배지 / 우측 **총액 `18px/800`** + `지급 준비 N원`
- 2행 메타: `구분  /  정산일 8/20 (목) D-19`(D-day는 `#B45309`, 완료는 `#15803D`)
- 3행 **세무자료 수집 바**: 높이 6, 전원 수집 완료면 green, 아니면 amber + `세무자료 4 / 8명`
- 보류 카드는 빨간 박스로 사유 한 줄 (`#FEF2F2` / `1px #FECACA` / `#B91C1C`)
- 액션: "대상 인원 보기 v"(펼침) + 주 버튼
  - 예정 -> **정산 완료로 기록**(amber) / 보류 -> 보류 사유 해결하기(아웃라인) / 완료 -> 정산 내역 보기

**펼친 표** `minmax(0,1fr) 130px 130px 100px`  -  인플루언서 / 페이 / 세무자료 / 상태
- 세무자료 칩: 수령 완료 `#F1F1F4` / `#5C5C68` / 미비 `#FEE2E2` / `#DC2626`

  **종류를 정한 것과 실제로 받은 것은 다른 문제**라 한 칩에서 구분해야 독촉 대상이 명확해진다
- 상태: 지급 완료(green) / 대기(회색) / 보류(red)

### 우측 레일
1. **송금 미대행 안내**(amber 박스)  -  위 [주의] 내용
2. **세무자료 안내**  -  세금계산서(사업자등록증 / 발행 주체) / 3.3%(주민번호 대신 **전화번호 / 국세청 ID**) +

## 화면 12. 인플루언서 마이페이지 (모바일 우선 + PC)  신규

파일: `influencer-mypage-mobile.dc.html` (390px)  /  `influencer-mypage-pc.dc.html` (1360 min)
구현 경로: `src/app/(dashboard)/influencer/dashboard/page.tsx`

[주의] **인플루언서는 모바일이 주 화면이다.** 광고주 콘솔(PC 전용)과 반대 방향이므로
컴포넌트를 억지로 공유하지 말고 각자 최적화한다. 공유하는 것은 **색 / 타이포 / 용어**뿐이다.

### 순서를 바꾼 것이 이번 작업의 핵심
레포 현재 순서는 캘린더 -> 빠른 액션 -> 대시 -> 알림 -> 내 오픈 -> 채널 분석 -> 매출이다.
모바일에서 매일 여는 화면의 첫 화면은 "이번 달 훑기"가 아니라 **"지금 나에게 온 일"** 이어야 한다.

```
프로필 + 매치 스코어 + 블로그 등급 + 크레딧        <- 내가 어떻게 보이는지
답을 기다리는 제안 배너 (amber)                    <- 가장 급한 것
이번 주 일정 (7일 스트립)                          <- 월 캘린더는 별도 탭으로
+ 오픈 등록 (주 CTA)  /  캠페인 찾기
받은 제안                                          <- 남이 나에게 건 일
진행중 협업 (단계 도트 + 다음 할 일 + D-day)        <- 내가 할 일
내 채널 분석                                       <- 내 상태
이번 달 수익
하단 탭바 5개 (홈 / 오픈 / 대시 / 내 채널 / 수익)
```
원칙: **남이 나에게 건 일 -> 내가 할 일 -> 내 상태** 순.
월 캘린더는 하단 탭 "오픈"으로 옮긴다  -  매일 보는 게 아니라 등록할 때 보는 화면이다.

### 모바일 세부
- 화면 폭 390, 상단바 52 sticky, 하단 탭바 고정(아이콘 17px + 라벨 10.5px, 활성만 컬러)
- 히어로: 아바타 56 + 별명 17px/800 + **매치 스코어 링 24px** + 블로그 등급 칩 + 검정 크레딧 카드
- 받은 제안 카드: 날짜 칩(파랑)  /  장소 칩(회색)  /  페이(우측 800) + **"대시 열기" 44px** + 거절 x
  -> 모바일 터치 타깃은 **44px 미만 금지**
- 진행중 협업: 7단계 도트(현재 단계만 amber 링) + 단계명 + 다음 할 일 + D-day(2일 이내 빨강)

- 수익: 이번 달 합계 + 정산 예정(amber)/지급 완료(green) 2칸 + 다음 정산일 + 미제출 경고

### PC 세부
광고주 콘솔과 **같은 셸**(사이드바 236  /  상단바 64  /  `min-width:1360`)을 쓰되 좌측 컬럼의 주인공이 다르다.

## [돈] 크레딧 정책 (확정) 

이 절은 **화면보다 규칙이 먼저**인 영역이다. 구현 전에 여기부터 읽을 것.

### 왜 지금 넣는가
크레딧은 당장의 수익원이 아니다. **나중에 과금할 수 있는 구조를 미리 심어두는 것**이 목적이다.
초기에는 활동 보상으로 넉넉히 지급해 사실상 무료로 쓰게 하고, 참여율이 오르면
지급량을 점차 줄여 자연스럽게 충전으로 넘어가게 한다.
-> 따라서 **초기 UI에서 크레딧을 크게 드러내지 않는다.** "유료 서비스"로 오해되면 역효과다.

### 1. 단위와 종류
- **1C = 1원**. 표기는 항상 대문자 `C` + 크레딧 마크(`logo/matchpost-credit.svg`). 예: `48,600 C`
- 크레딧은 **두 종류**다. 화면에는 합계 하나만 보이고, 원장에서만 구분한다.

| 지갑 | 생기는 경로 | 환불 | 만료 |
| --- | --- | --- | --- |
| `free` (무상) | 웰컴  /  활동 보상  /  관리자 지급 | **불가** | 없음 (아래 주의) |
| `paid` (유상) | 사용자 충전  -  **1단계에서는 미구현** | 미사용분 환불 가능 | 없음 (법정 5년) |

[주의] **두 지갑 분리는 지금 해야 한다.** 유상 크레딧에는 환불 의무 / 부가세 / 소멸시효가 걸리고
무상에는 걸리지 않는다. 한 통에 섞어 저장하면 나중에 절대 분리할 수 없다.
충전 기능이 없더라도 `wallet` 컬럼은 처음부터 넣는다.

[주의] **만료: 날짜 기준이 아니라 방문 기준이다.** 아래 "6. 방문 기반 증감" 참조.
시간이 지나면 사라지는 게 아니라 **안 오면 사라진다.** 유저가 통제할 수 있고 명분도 선다.
초기에 뿌린 크레딧이 영구 부채로 남는 문제도 이 장치가 해결한다.
`expires_at` 컬럼은 그래도 만들어 두되 값은 항상 `null`  -  나중에 날짜 만료를
**신규 지급분에만** 붙이고 싶어질 때 마이그레이션이 필요 없어진다.

**소진 순서**  -  차감 시 `free` 를 먼저 쓰고, 부족분만 `paid` 에서 뺀다.
(만료를 도입하면 그 안에서 만료 임박순.) 유상분을 마지막까지 남겨 환불 분쟁을 줄인다.

### 2. 원장 (credit_ledger)
[주의] **`users.credit_balance` 같은 숫자 컬럼을 더하고 빼지 말 것.** 분쟁 시 아무것도 증명하지 못한다.
거래를 append-only 로 쌓고 잔액은 합계로 파생시킨다.

```sql
credit_ledger
  id           uuid pk
  user_id      uuid  fk
  delta        int          -- 지급 +, 차감 -
  wallet       text         -- 'free' | 'paid'
  kind         text         -- 'welcome'|'reward'|'charge'|'refund'|'purchase'|'penalty'|'admin'
  reason_code  text         -- 아래 표의 코드. 유저 화면 문구가 여기서 파생된다
  ref_type     text         -- 'schedule'|'campaign'|'proposal'|'deal'|'review'|'invite'|null
  ref_id       uuid
  memo         text         -- 관리자 내부 메모. 유저에게 노출 안 함
  admin_id     uuid         -- kind='admin' 일 때만
  expires_at   timestamptz  -- 현재 항상 null
  created_at   timestamptz
```
- 잔액 = `sum(delta) where user_id = ?` (뷰 또는 캐시 컬럼 + 트리거)
- **모든 행은 불변**이다. 취소 / 환불은 기존 행 수정이 아니라 **반대 부호의 새 행**으로 남긴다
- 차감 트랜잭션은 잔액 확인 -> insert 를 한 트랜잭션에서. 동시 요청으로 잔액이 음수가 되면 안 된다

### 3. 차감  -  무엇에 크레딧을 쓰는가
**원칙: 남의 주의(attention)를 점유하는 행위에만 과금한다.**
검색  /  프로필 열람  /  메시지 읽기는 영원히 무료. 상대의 달력이나 받은 편지함에
자리를 차지하는 행동에만 쓴다. 이 원칙은 스팸 방지와 방향이 같아서,
나중에 단가를 올려도 "돈 뜯는다"가 아니라 "품질 관리"로 읽힌다.

| 행위 | 대상 | 차감 | reason_code |
| --- | --- | --- | --- |
| 오픈 일정 등록 (**1건**  -  하루든 기간이든) | 인플루언서 | 1,000 C | `open_schedule` |
| 캠페인 개설 | 광고주 | 5,000 C | `create_campaign` |
| 제안 보내기 (대시 시작) | 광고주 | 500 C | `send_proposal` |
| 상세 프로필 열람 (1인당) | 광고주 | 1,000 C | `unlock_profile` |

- **연락처는 크레딧으로 살 수 없다.** `unlock_profile` 이 여는 것은 상세 프로필(과거 성과 / 단가 / 
  상세 통계)까지다. 전화번호는 **양쪽 확정 이후에만** 열린다  -  아래 "연락처 공개" 참조
- **오픈은 날짜 수와 무관하게 1건이다.** 달력에서 여러 날을 골라도 `schedules` 1행으로 묶여
  1,000 C 만 차감한다. 날짜별로 과금하면 일정을 적게 여는 쪽으로 유인이 생기는데,
  오픈은 많을수록 좋은 재고라 방향이 정반대다. 기간형(숙박 등)도 같은 1건
- **열람은 1회 결제 후 영구**다. 같은 인플루언서를 다시 열어도 다시 받지 않는다
- **제안은 대화 시작 시 1회**다. 메시지 수와 무관하다
- 캠페인 **상단 노출 / 추천 배치**는 향후 별도 광고 상품으로 추가한다 (차감액 미정, 이번 범위 밖)
- **인플루언서 채널 분석 열람**도 향후 과금 후보다  -  크레딧 차감 또는 구독 회원 전용.
  [주의] 지금은 무료지만, 나중에 잠글 수 있도록 **분석 상세를 별도 뷰/엔드포인트로 분리**해 둘 것.
  프로필 응답에 분석 데이터를 통째로 실어 보내면 나중에 못 잠근다.

### 4. 지급  -  무엇에 크레딧을 주는가
[주의] **프레이밍 주의.** "참여하면 상쇄된다"로 설명하지 말 것.
나중에 보상을 줄일 때 유저는 **약속 파기**로 받아들인다.
처음부터 **성과에 대한 보상**으로 둔다  -  협업을 완료했다, 후기를 썼다.
그래야 나중에 줄여도 "정책 조정"으로 읽힌다.

| 계기 | 대상 | 지급 | reason_code | 비고 |
| --- | --- | --- | --- | --- |
| 가입 축하 (웰컴) | 양쪽 | 30,000 C | `welcome` | 첫 로그인 시 1회 |
| 프로필 / 채널 연동 완료 | 양쪽 | 3,000 C | `profile_complete` | 계정당 1회 |
| 첫 오픈 등록 / 첫 캠페인 개설 | 양쪽 | 3,000 C | `first_action` | 계정당 1회 |
| 응원 크레딧 | 양쪽 | 500 C | `encourage` | 오픈 / 캠페인을 열 때마다 |
| 축하 크레딧 | 양쪽 | 2,000 C | `celebrate` | 그 오픈 / 캠페인이 협업으로 성사되면 |
| 협업 완료 | **양쪽 모두** | 3,000 C | `deal_complete` | 정산 완료 시점 |
| 후기 / 평점 작성 | 양쪽 | 1,000 C | `review` | 종료 후 7일 이내 |
| 친구 초대 | 초대자 | 5,000 C | `invite` | 피초대자가 **첫 활동을 마쳐야** 지급 |
| 꾸준히 들르기 | 양쪽 | 500 C | `visit_weekly` | 한 주 5일 이상 방문  /  주 1회 정산 |
| 한 달 개근 | 양쪽 | 2,000 C | `visit_monthly` | 한 달 20일 이상 방문 |
| 오랜만에 돌아오기 | 양쪽 | 1,000 C | `comeback` | 30일 이상 공백 후 복귀 시 1회 |

**웰컴 30,000 C = 약 석 달치 활동.** 인플루언서 기준 월 4건 오픈(4,000 C) x 3개월.
초기 유저가 크레딧을 의식하지 않고 세 달을 쓸 수 있는 양이다.

**순증 구조 (의도된 것)**  -  인플루언서가 오픈 1건을 열어 협업까지 가면
`-1,000 +500 +2,000 +3,000 +1,000 = +5,500`. 활동할수록 잔액이 는다.
서비스가 자리 잡으면 `encourage` / `celebrate` 부터 축소해 이 구간을 좁힌다.

### 5. 환불  /  페널티
| 상황 | 처리 |
| --- | --- |
| 오픈 / 캠페인 취소  -  **양쪽 확정 전** | 차감액 **전액 환불** (`kind='refund'`) |
| 오픈 / 캠페인 취소  -  **양쪽 확정 후** | **환불 없음** + 같은 금액 추가 차감(`kind='penalty'`) + 성실도 지표 반영 |
| 상대가 취소한 경우 | 내 차감분은 전액 환불. 페널티는 취소한 쪽에만 |
| 무상 크레딧 현금 환불 | **불가** |
| 충전 크레딧 현금 환불 | 미사용분에 한해 가능 (충전 기능 도입 시) |

[주의] 확정 후 취소 페널티는 대시 확정 바 안내문과 **문구가 일치해야 한다**  - 
인플루언서 대시: `확정하면 협업이 시작되고 취소 시 페널티가 있어요.`

### 6. 방문 기반 증감 (활성화 장치) 

**목적**  -  방문 습관을 만드는 것. 크레딧을 "쓰지 않으면 사라지는 것"이 아니라
**"들르면 늘고, 안 들르면 주는 것"** 으로 만든다.

**늘어나는 쪽**
| 조건 | 지급 | reason_code |
| --- | --- | --- |
| 한 주 5일 이상 방문 | +500 C | `visit_weekly` |
| 한 달 20일 이상 방문 | +2,000 C | `visit_monthly` |
| 30일 이상 공백 후 복귀 | +1,000 C (1회) | `comeback` |

**줄어드는 쪽  -  정액 차감**
| 미방문 기간 | 차감 | reason_code |
| --- | --- | --- |
| 7일 | 없음  -  **알림만** |  -  |
| 14일 | -500 C (1회) | `dormant_14` |
| 30일 이후 | -1,000 C, **이후 30일마다 반복** | `dormant_30` |

[주의] **비율 차감이 아니라 정액이다.** 잔액에 비례해 깎으면 열심히 쌓은 사람을 더 깎게 되어
보상 정책과 정면으로 충돌한다. 누구에게나 같은 금액.

**반드시 지킬 세 가지**
1. **무상 지갑(`free`)만 차감한다.** 충전분(`paid`)은 어떤 경우에도 건드리지 않는다  -  법적 위험
2. **하한선 5,000 C.** 잔액이 5,000 C 이하면 차감하지 않는다. 복귀했을 때 아무것도 못 하는
   상태를 만들면 그대로 이탈한다. 차감으로 5,000 C 아래로 내려갈 상황이면 5,000 C 에서 멈춘다
3. **차감 3일 전 예고 알림 필수.** 알림 없이 깎으면 신뢰가 한 번에 무너진다.
   알림 문구는 협박이 아니라 초대여야 한다  -  `3일 뒤 크레딧이 1,000C 줄어들어요. 잠깐 들러보세요.`

**구현 노트**
- 일일 방문은 원장에 쌓지 않는다. `user_visit_log(user_id, visited_on)` 에 **하루 1행**만 남기고,
  주간 / 월간 배치가 집계해 원장에 **1행씩** 지급한다. 매일 지급하면 원장이 폭증한다
- 차감도 배치(일 1회)로 돌린다. 마지막 방문일은 `users.last_visited_at`
- "방문"의 정의: **로그인 상태로 앱/웹을 연 것**. 알림 클릭이나 이메일 열람은 방문이 아니다
- 차감 행도 반드시 원장에 남긴다(`kind='decay'`). 유저 내역에 `휴면` 칩(`#FEE2E2/#DC2626`)으로 표시

### 7. UI 노출 강도  -  조용히
- 사이드바 하단 잔액 카드 **하나만** 상시 노출. 그 외 화면에서는 크레딧을 말하지 않는다
- 차감이 일어나는 순간(오픈 등록  /  캠페인 개설  /  제안 발송)에만 금액을 보여준다
- 잔액 부족 경고는 **실제로 부족할 때만**. 초기에는 사실상 발생하지 않는다
- 배지  /  카운트다운  /  적립 애니메이션처럼 게임처럼 보이게 하는 장치는 **쓰지 않는다**
- 대신 **"크레딧 안내" 페이지**를 두어 궁금해하는 유저가 스스로 찾아오게 한다

### 8. 화면 3종 (`크레딧.dc.html`)

**1) 크레딧 안내** (`/credits/about`)  -  유저용 설명 페이지, 최대폭 920
검정 히어로(`활동하면 쌓이고, 쌓아둘수록 유리해집니다`) -> 3개념 카드 ->
`이렇게 쌓입니다` / `이럴 때 씁니다` 2열 -> `지금 쌓아두면 좋은 이유` 3단 -> FAQ 5.
"검색과 열람은 무료입니다" 앰버 박스를 반드시 넣는다  -  가장 많이 오해하는 지점이다.

**2) 크레딧 내역** (`/credits`)  -  광고주 / 인플루언서 **공통 화면**, 최대폭 920
검정 잔액 카드 + `이번 달 쌓임`(초록) / `이번 달 사용` 3칸 ->
필터 칩(전체/쌓임/사용) -> 표 `날짜  /  내용  /  관련  /  변동  /  잔액`.
종류 칩 색: 지급 / 보상 `#DCFCE7/#15803D`  /  사용 `#F1F1F4/#5C5C68`  / 
환불 `#DBEAFE/#1D4ED8`  /  차감(페널티) `#FEE2E2/#DC2626`.
표 하단 고정 문구: `잔액은 거래 기록의 합계입니다...`  -  원장 구조를 유저에게 설명하는 줄이다.

**3) 관리자 지급** (`/admin/credits/grant`)
좌: 대상 선택 3모드  -  **개별 검색 / 조건 그룹 / 전체 일괄**.
조건 그룹은 미리 정의된 세그먼트 체크박스(협업 완료자, 미활동자, 응답률 상위, 다회 개설 광고주).
전체 일괄은 **빨간 경고 박스** 필수.
우(sticky): 1인당 지급액 + 프리셋 칩 -> **사유(필수, 유저 내역에 노출)** -> 내부 메모(비노출) ->
유효기간 체크박스(**현재 비활성**  -  정책상 만료 없음) -> 앰버 미리보기(`총액 = 대상 수 x 단가`) -> 지급 실행.
하단: 감사 로그 표(`일시 / 대상 / 사유 / 1인당 / 총액 / 처리자`). **취소 불가**이므로 실행 전 확인 다이얼로그를 붙인다.

### 9. 구현 순서
1. `credit_ledger` 테이블 + 잔액 뷰 + 차감/지급 서버 액션(트랜잭션)
2. 차감 4지점 연결  -  오픈 등록  /  캠페인 개설  /  제안 발송  /  프로필 열람
3. 지급 8지점 연결  -  웰컴부터. `deal_complete` 는 정산 완료 훅에 붙인다(`settleCampaign`)
4. 크레딧 내역 화면 (공통 컴포넌트 1개, 양쪽 마이페이지에서 재사용)
5. 크레딧 안내 페이지
6. 관리자 지급 화면 + 감사 로그
7. `user_visit_log` + 주간/월간 집계 배치 + 휴면 차감 배치 + 예고 알림
8. (향후) 충전  /  결제 연동  /  유상 지갑 활성화
9. (향후) 채널 분석 열람 과금  -  크레딧 차감 또는 구독 전용

##  정산 성실도 (광고주 신뢰 지표) 

**문제**  -  연락처가 결제 등록 시점에 닫히므로, 결제를 미루는 광고주는 제재가 없다.
반대로 인플루언서는 "이 브랜드가 제때 돈을 주는가"를 **협업을 시작하기 전에** 알 방법이 없다.

**해법**  -  캠페인 등록 시 기재한 **결제 예정일**과 실제 **결제 등록일**을 비교해 집계하고,
그 결과를 인플루언서에게 보여준다.

### 판정
```
campaigns.payment_due_date   -- 등록 시 광고주가 기재 (필수 입력)
deals.settled_at             -- 딜시트에서 결제 등록이 완료된 시각
지연일 = max(0, date(settled_at) - payment_due_date)
```
- **3일까지는 지연으로 세지 않는다.** 은행 영업일 / 경리 마감 시차가 있다
- 4일 이상부터 `late`. 지연일수도 함께 저장한다
- **인플루언서 귀책으로 미뤄진 건은 제외**  -  원고 마감 지연, 수정 요청 미응답 등으로
  게재가 늦어진 경우. 이 판정은 딜시트의 단계 타임스탬프로 자동 계산한다
- 광고주가 예정일을 **사후에 변경한 경우** 원래 값을 기준으로 한다 (`payment_due_date_original`)

### 표시 규칙
| 조건 | 표시 |
| --- | --- |
| 최근 12개월 협업 **3건 미만** | `기록 쌓이는 중`  -  비율을 내지 않는다 |
| 정시 정산률 90% 이상 | 초록  /  `최근 12개월 N건 모두 제때 정산했어요` |
| 90% 미만 | 앰버  /  `최근 12개월 N건 중 M건 지연  /  평균 D일` |

[주의] **표시는 사실 집계만.** "나쁜 광고주" 같은 낙인 문구, 빨간 경고, 순위표는 만들지 않는다.
사실만 보여주고 판단은 인플루언서가 한다. 집계 기준(12개월 / 3일 유예 / 3건 이상)을
안내 페이지에 공개해 두면 분쟁 시 근거가 된다.

### 노출 지점
1. **인플루언서 대시 -> 우측 "받은 제안" 레일 -> "이 브랜드와" 블록** (구현됨)
    -  확정을 누르기 직전에 보이는 자리다. 여기가 가장 중요하다
2. 캠페인 찾기 목록  -  카드에 작은 점 + `정산 N%`
3. 브랜드 정보 팝업  -  상세(지연 이력 건수, 평균 지연일)

### 광고주 쪽 압박 장치
- 결제 등록 전까지 **딜시트 / 정산 / 대시보드에서 계속 "진행중"** 으로 남는다. 완료로 넘어가지 않는다
- 광고주 대시보드 KPI: `정산 대기 N건`  -  예정일이 지났으면 **빨강 + `D+3 지연`** 표기
- 예정일 D-3, D-day, D+1, D+7 알림 발송
- 지연 건이 있으면 **새 캠페인 개설 시 경고 배너** (막지는 않는다. 1단계에서는 경고까지만)

## 딜시트와의 계약 (같은 함수를 부른다)

### 1. 정산  -  정산 화면 <-> 딜시트
두 화면은 **같은 `proposals.settlement_status` 를 다른 각도로 보는 뷰**다.
정산 화면 = 캠페인을 가로질러, 딜시트 = 한 캠페인 안.

`settleCampaign(campaignId)` 하나를 두고 양쪽에서 호출한다. 이 함수가 하는 일:
1. 해당 캠페인의 **대상** `proposals` 전체를 `settlement_status = '완료'` 로 (개별 아님, 트랜잭션 1건)
    -  대상 = 게재 확인 + 세무자료 수령 완료. **보류 건은 건드리지 않는다**
2. 각 `proposals.stage` 를 마지막 단계(**정산**)로 올린다
3. 알림 발생  -  광고주(기록 완료)  /  인플루언서(정산 처리됨) 양쪽
4. 종료 보고서용으로 정산 완료 일시를 남긴다

반영되는 화면:
| 화면 | 변화 |
| --- | --- |
| 딜시트 정산 열 | "지급 완료"(green) |
| 딜시트 진행 단계 도트 | 마지막 **정산** 까지 채워짐 |
| 딜시트 하단 일괄 정산 바 | 대상 0명 -> 바 숨김 |
| 정산 화면 | "예정" -> **"완료"** 탭으로 이동, 요약 4칸 재계산 |
| 알림 | "정산이 완료되었어요" 행 추가 |

[주의] 역방향도 동일하다  -  딜시트 일괄 정산 바에서 눌러도 정산 화면이 따라와야 한다.
[주의] **송금은 하지 않는다.** 이 함수는 기록만 바꾼다(문구도 "정산 완료로 기록").

### 2. 세무자료 수령 체크  -  딜시트 <-> 정산 화면
딜시트에서 체크하면 정산 화면의 **세무자료 수집 바**와 "세무자료 미비 N명" 요약이 즉시 바뀐다.
반대로 정산 화면에서 "세무자료 일괄 요청"을 보내면 딜시트 행에 요청 시각이 남는다.
`tax_doc_type`(종류 정함)과 `tax_doc_received`(실제 받음)는 **별개 필드**다  -  칩 라벨 3단(`세금계산서` / `3.3% 미수령` / `종류 미정`)이 이 두 필드의 조합이다.
