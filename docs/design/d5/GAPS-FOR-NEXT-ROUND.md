# D5 구현 후 남은 갭 — 다음 핸드오프에서 확인해줄 것

## 0. C2(팀 초대) — 초대 관리는 완료, 실제 권한 전파는 안 함

`team_members` 테이블 + 초대/역할변경/재발송/재활성화 화면(`/advertiser/team`)은 완료했고,
가입 시 이메일 매칭으로 자동 연결도 된다(사용자 결정: 팀원은 새 계정으로 가입해서 연결).

**하지만 담당자로 로그인한 사람이 실제로 오너의 캠페인·제안·정산에 접근하는 권한 전파는
안 했다.** 지금 앱은 거의 모든 조회가 `advertiser_id = 로그인한 사용자` 기준이라(대시보드/
캠페인목록/정산화면/메시지 등 15곳 이상), 팀원이 로그인해도 자기 자신의(비어있는) 계정만
보인다. 이걸 제대로 하려면 각 조회 지점을 "내 id 또는 내가 속한 team의 owner_id"로 넓히고
RLS까지 맞춰야 하는데, 잘못 넓히면 다른 광고주 데이터가 새는 보안 사고로 이어질 수 있어서
한 번에 급하게 할 일이 아니라고 판단해 이번엔 빼뒀다. 다음 라운드에서 "팀원이 실제로 뭘
볼 수 있어야 하는지"(오너와 완전히 동일 화면인지, 일부만인지)를 정해주면 그 기준으로
전체 조회 지점을 훑는 별도 작업으로 진행하는 게 안전하다.

> SPEC-B-SETTLE.md(화면11/12·크레딧 정책·정산 성실도)를 구현하면서 발견한, 스펙만으로는
> 결정할 수 없어서 이번엔 건드리지 않은 부분들이다. 클로드 디자인 쪽에서 다음 라운드 문서를
> 만들 때 참고해달라고 남겨둔다.

## 1. 초대(invite) 기능 — 완전 신규, 화면 스펙 없음

크레딧 표에 "친구 초대 5,000C, 피초대자가 첫 활동을 마쳐야 지급"이라고 금액·조건은 있지만,
그걸 실제로 발동시킬 초대 링크 생성, 추천인 추적(누가 누구를 초대했는지), 가입 시 추천 코드
입력 흐름 자체가 레포에 전혀 없다. `profiles`에 추천인 컬럼도 없음.
→ 화면/데이터모델 스펙이 오면 그때 구현.

## 2. 상세 프로필 열람(unlock_profile 1,000C) — "무엇을 잠그는지"가 없음

지금 `/profile/[id]` 페이지는 전부 무료로 공개돼 있다. 스펙은 이 열람에 과금하라고 하는데,
공개 정보와 "상세"(잠긴) 정보를 어떻게 나눌지가 정의돼 있지 않아 손대지 않았다.
`creditConfig.ts`에는 금액(1,000C)만 미리 확정해 둔 상태로 남겨둔다.

## 3. 관리자 크레딧 지급 화면 — 지금은 개별 검색만

`/admin/credits`는 이미 있지만 유저 검색 후 1명씩 지급하는 방식뿐이다. 스펙의 3모드
(개별 검색 / 조건 그룹 세그먼트 / 전체 일괄 + 빨간 경고박스)와 별도 감사 로그 표는
이번엔 안 만들었다 — 지금 방식으로도 기능은 되기 때문에 우선순위를 낮췄다.

## 4. 정산 성실도 — 노출 지점 일부 미구현

- ✅ 인플루언서 대시 "받은 제안" 카드 — 광고주별 정산 정시율(`advertiser_payment_score` 뷰) 노출함
- ✅ `/influencer/search` 캠페인 카드 — 정산 N% 점 노출함
- ❌ 브랜드 정보 팝업(지연 이력 건수·평균 지연일 상세) — 그런 팝업 자체가 없어서 안 만듦
- ❌ 광고주 대시보드 KPI "정산 대기 N건" — 대신 `/advertiser/settlements` 화면에 더 정확한
  같은 정보(정산 예정 합계·건수)가 이미 있어 중복이라 생략함
- ❌ 지연 이력 있으면 새 캠페인 개설 시 경고 배너 — 미구현

**판정 로직 근사치**: "인플루언서 귀책으로 미뤄진 건은 제외"를 정확히 판정할 필드가 없어서,
draft/publish 체크포인트가 지연 없이 끝난 건만 "광고주 귀책 지연" 대상으로 근사했다
(`sql/migrations/0062_advertiser_payment_score.sql` 주석 참고). 더 정밀한 귀책 판정 규칙이
필요하면 다음 라운드에서 정해줄 것.

## 5. 인플루언서 새 셸 — 대시보드 한 곳에만 적용

`InfluencerShell`(PC 사이드바 + 모바일 하단탭)은 `/influencer/dashboard`에만 붙였다. 나머지
9개 페이지(검색/오픈/메시지/알림/수익/프로필/채널분석/제안/오픈목록)는 기존 `TopBar`를 그대로
쓴다 — 하단탭에서 그 페이지들로 이동하면 새 셸이 사라진다. 전체 확장은 9개 파일을 다 건드리는
큰 작업이라 이번 라운드에서 범위를 좁혔다(사용자 확인 후 결정).
