## A. 대시(메시지) 상태 규칙 — 가장 중요

| # | 규칙 | 지금 무엇이 문제인가 |
| --- | --- | --- |
| A1 | **대화를 열면 그 대화는 읽음.** 목록 미응답 배지 · 필터 수 · 사이드바 배지 · 대시보드 요약 카드가 **한 값에서 파생** | 요약 카드를 별도 배열/카운트로 두면 대시에서 읽어도 홈에 미응답이 남는다 |
| A2 | **필터 수는 지금 탭(캠페인 대화 / 개인 대화)에 보이는 목록만 센다** | 두 탭을 합쳐 세면 목록 7개 위에 「전체 9」가 뜬다 |
| A3 | **대시 보내기 = 대화 개설.** `proposals` 행 생성 → 상태 `응답 대기` → **그 대화를 연다** | 확인 팝업만 닫히면 보냈는지 알 수 없다 |
| A4 | **팝업 문구 두 가지** — 새로 보내기 / 조건 바꿔 다시 보내기. 다시 보낸 사실은 대화에 시스템 줄로 남고, 「무응답 N일」 문구도 갱신 | 베타 기간 대시 크레딧 0 (`0057_dash_fee_beta_free.sql` 과 일치) |
| A5 | **협업 조건 수정은 입력창 프리필**(`협업 조건을 이렇게 바꾸고 싶어요 — `), 별도 팝업 아님 | 조건은 상대와 합의해야 바뀐다 |
| A6 | **취소 요청은 사유 필수.** 보내면 사유가 대화에 남고 확정 바가 `취소 요청 보냄 · 상대 수락 대기` + `요청 철회` 로 바뀐다. 상대 수락 전까지 협업은 유효 | `0053_cancellations_functions.sql` 흐름과 일치. 사유 없는 취소는 상대가 판단할 근거가 없다 |
| A7 | **내 수락은 상대 수락 전까지 철회 가능** (광고주·인플루언서 동일). 그 상태의 버튼 라벨은 `내 수락 취소` | 라벨이 `협업 수락`인데 누르면 풀리는 버튼이 있었다 |

## B. 정산 화면 규칙 (4차 이후 확정)

대상: 광고주 정산 화면(아직 레포에 없음) · `SettleConfirmModal.tsx`

- B1 **세무자료 미수령이 남으면 정산 기록 CTA를 잠그되, 그 자리에서 「세무자료 N명 요청하기」**를 띄운다.
  보내면 버튼이 `요청 보냄 · 대기`. — 막혔다고만 말하는 버튼은 일을 진행시키지 못한다
- B2 **전원 수령이어야 정산 완료 기록 가능.** 「미수령 N명 제외」 같은 부분 정산 문구를 쓰지 않는다
- B3 **모바일도 같은 규칙.** 화면 크기에 따라 정산 규칙이 달라지면 안 된다 (모바일은 요청·기록만)
- B4 **「사유 해결 표시」는 기록만.** 누르면 `해결 기록됨 · 오늘` + 팀 감사기록 한 줄, 개별 정산 버튼이 열린다.
  **지급 자체는 딜시트에서 사람이 따로 누른다**

## C. 그 밖의 작은 확정

- C1 캠페인 목록 정렬 라벨은 **「등록 최신순 / 등록 오래된순」** — 표에는 진행일만 보이므로 기준을 라벨에 밝힌다
- C2 팀 초대는 이메일+역할 → **「초대 대기」로 표·KPI 즉시 반영**, 역할 변경·재발송·재활성화 동작
- C3 **모바일에서 할 수 없는 일은 커서·화살표를 빼고 「PC에서」 배지.** 되돌릴 수 없는 처리는 PC 전용
- C4 오픈 채널 선택은 다중 토글, 내 오픈 목록 행은 **대시가 온 오픈만** 대화로 (0건은 커서 없음)
