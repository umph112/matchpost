```
handoff_D17 폴더를 docs/design/d17/ 에 넣고 커밋해줘 (.dc.html · support.js 함께).

그다음 D17-COPY-EARNINGS-BRAND.md 를 1절부터 순서대로. 세 덩어리이고 1절이 제일 작아.

1절 — 빠진 안내 문구 2건 (네가 D16 에서 「PC 에도 없다」고 알려준 것)
  · 「단체 발송」 배지 옆에 「참여자 모두에게 같은 내용이 갔어요」
    배지만 있으면 인플루언서가 「이게 나한테만 온 건가」를 판단할 근거가 없어
  · 개별 발송 배지에 「다른 참여자에게는 가지 않았어요」 (없으면 함께)
  · 날짜 제안 카드에 부제 — 「오픈해두신 날짜예요」 / 「오픈해두신 날짜와 다른 날이에요」
    부제가 없으면 광고주가 오픈해둔 날짜인지 모른 채 수락해
    판정은 그 인플루언서의 오픈 날짜(schedules)와 비교.
    오픈이 없는 상대(친구 등)면 부제를 생략해 — 비교 대상이 없어

2절 — 매출 화면 (D7 에서 지적하고 미착수)
  · 미수 카드에 D+ · 금액 · 「지연 알림 N회 발송 (매일 1회)」
    광고주·관리자 화면은 이 값을 보여주는데 인플루언서 화면만 없어.
    세 화면이 같은 값을 보여야 해 — 얼마나 밀렸고 얼마를 못 받았는지 알아야 하잖아
    D+ 는 lib/date.ts 의 dDayLabel 을 써. 날짜는 2026-08-01 이 아니라 8/01
  · 상태 필터 「완료」와 「결제완료」가 화면에서 구분이 안 돼.
    광고주 정산 용어(예정 · 미수 · 완료)와 맞춰줘.
    문서 2-3 에 매핑을 적었는데 실제 데이터와 다르면 멈추고 알려줘
  · 목록 행이 e.category 를 쓰고 있으면 회사명으로 바꿔.
    돈이 걸린 화면에는 브랜드가 아니라 회사명이야 — 통장에 찍히는 이름과 달라지면
    입금 확인을 못 해

3절 — 대시 헤더 브랜드 (보류했던 것)
  · 먼저 conversations.campaign_id 가 실제로 채워지는지 확인해줘 (문서 3-2)
  · 컬럼 자체가 없으면 멈추고 알려줘. 스키마 결정이 필요해
  · 채워지면 캠페인 대화 헤더에 {brand_name ?? company_name} + 캠페인 제목
  · 「대행」 배지는 붙이지 마. 브랜드명이 상호와 다르면 그게 대행이고,
    대행이라는 사실은 화면이 말하지 않고 대화에서 사람이 밝혀

절 단위로 끊어서 하고 각 절 끝에 보고해줘.
1절은 PC·모바일 공통 컴포넌트라 한 번 고치면 양쪽에 반영될 거야.

판단이 필요하거나 문서와 실제 코드가 어긋나면 추측하지 말고 멈춰서 물어봐.
끝나면 4절 grep 과 체크리스트 결과를 알려줘.
```
