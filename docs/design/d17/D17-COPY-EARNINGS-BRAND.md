# D17 — 남은 문구 · 매출 화면 · 대시 헤더 브랜드

세 덩어리입니다. **1절이 가장 작고 효과가 큽니다.**

---

# 1. 빠진 안내 문구 2건 (PC·모바일 공통)

D16 조사에서 **PC 에도 없는 것**으로 확인됐습니다. 배지·값만 있고 그것이 무슨 뜻인지 말해주는
문장이 없습니다.

## 1-1. 단체 발송 배지 부제

```
src/components/messages/MessageBubble.tsx
```

지금은 「단체 발송」 배지만 있습니다. 배지만 보면 인플루언서가 **「이게 나한테만 온 건가」**를
판단할 근거가 없습니다.

```
배지 옆에 붙임:
  「참여자 모두에게 같은 내용이 갔어요」
  font-size:10px · color:#93A3B8
배지와 gap:5px · 배지 줄 전체가 말풍선 위에 margin-bottom:4~5px
```

같은 자리의 **개별 발송** 배지에도 짝이 되는 문장이 있습니다:
```
「OOO님에게만」 + 「다른 참여자에게는 가지 않았어요」  (10px · #93A3B8)
```
이것도 없으면 함께 넣으세요.

## 1-2. 날짜 제안 카드 부제

```
src/components/messages/MessageBubble.tsx (날짜 제안 카드)
```

부제가 없으면 **광고주가 오픈해둔 날짜인지 다른 날인지 모른 채** 수락합니다.

```
날짜(16px/800) 아래:
  오픈해둔 날짜와 같으면  「오픈해두신 날짜예요」
  다르면              「오픈해두신 날짜와 다른 날이에요」
  font-size:11px · color:#92702A · margin-top:4px

그 아래 (기존 것 확인):
  내 제안   「상대가 수락하면 이 날짜로 확정돼요」  11px · #B0B0BB
  상대 제안 「이 날짜로 수락」 버튼
  수락됨    「✓ 확정됨 · 딜시트에 반영」  #DCFCE7 / #15803D
```

판정은 **그 인플루언서가 열어둔 오픈 날짜(`schedules`)와 비교**합니다.
오픈이 없는 상대(친구 등)면 부제를 생략하세요 — 비교 대상이 없습니다.

# 2. 매출 화면 정비 (D7 §5-4 미착수분)

```
src/app/(dashboard)/influencer/earnings/page.tsx
```

## 2-1. 미수 카드에 값이 없다

지금 「정산 예정일 2026-08-01이 지났어요」뿐입니다. 광고주 화면과 관리자 모니터는
D+ 와 금액을 보여주는데 여기만 없습니다. **세 화면이 같은 값을 보여야 합니다** (D6 C6).

```
D+       dDayLabel(settlementDate) — lib/date.ts 에 이미 있음
금액     그 캠페인의 내 페이(budget)
지연 알림 「광고주에게 지연 알림 N회 발송 (매일 1회)」
         N = 오늘 − 예정일 (일수). 배치가 매일 1회 보내므로 일수와 같다
날짜 형식 2026-08-01 이 아니라 8/01
```

이 세 값이 있어야 인플루언서가 **얼마나 밀렸고 얼마를 못 받았는지** 압니다.

## 2-2. 회사명 · 담당자

미수 카드에 이미 회사명 링크가 있습니다(D13). 담당자 이름이 함께 있는지 확인하세요:
```
「{회사명} / {담당자이름}」  — 슬래시 표기. 회사명 부분만 /advertiser/{id} 링크
```
띄어쓰면 어디까지가 회사인지 안 읽힙니다.

## 2-3. 상태값이 겹친다

```
STATUS_FILTERS = ['전체', '예정', '진행중', '완료', '결제완료']
```

「완료」와 「결제완료」가 무엇이 다른지 화면에서 구분되지 않습니다.
광고주 정산 쪽 용어(**예정 · 미수 · 완료**)와 맞추세요. 같은 건을 두 화면이 다른 이름으로
부르면 안 됩니다.

- 「진행중」 = 협업이 진행 중이고 정산일이 아직 안 옴 → **예정**
- 「완료」 = 게재는 끝났는데 지급 기록이 없음 → **미수**
- 「결제완료」 = 지급 기록됨 → **완료**

이 매핑이 실제 데이터와 맞는지 확인하고, 다르면 멈춰서 알려주세요.

## 2-4. 목록 행에는 브랜드가 아니라 회사명

D13 에서 정한 규칙입니다 — **돈이 걸린 화면에는 회사명**입니다.
통장에 찍히는 이름과 달라지면 입금 확인을 못 합니다. 지금 `e.category` 를 쓰고 있으면
회사명으로 바꾸세요.

# 3. 대시 헤더 브랜드 (D13 §5 보류분)

```
src/app/(dashboard)/*/messages/[id]/page.tsx
```

## 3-1. 왜 보류였나

대화가 캠페인에 묶이지 않아(`conversations.campaign_id` 가 비어 있음) 브랜드를 찾을 경로가
없었습니다. 억지로 넣으면 대화마다 다른 경로로 이름을 찾게 되어 더 꼬입니다.

## 3-2. 먼저 확인

```bash
grep -rn "campaign_id" src/lib/deals/ src/app/api/ | grep -i conversation
```

`get_or_create_conversation()` 이 `campaign_id` 를 받는지 보세요.

| 상태 | 할 것 |
| --- | --- |
| 받고 채워짐 | 3-3 진행 |
| 컬럼은 있는데 항상 null | 캠페인 대화 생성 시점에 채우고, 기존 행은 백필 |
| 컬럼 자체가 없음 | **멈추고 알려주세요.** 스키마 결정이 필요합니다 |

## 3-3. 표시

```
캠페인 대화 헤더:  {brand_name ?? company_name} + 캠페인 제목
개인 대화 헤더:    상대 이름 (지금 그대로)
```

브랜드는 **고르는 화면**의 규칙이 아니라 「무엇을 홍보하는 건인지」라서 대화에도 맞습니다.
다만 **「대행」 배지는 붙이지 마세요** — 브랜드명이 회사 상호와 다르면 그게 대행이고,
대행이라는 사실은 화면이 말하지 않고 대화에서 사람이 밝힙니다.
