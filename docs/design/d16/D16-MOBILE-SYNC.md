# D16 — 모바일 규칙 동기화

대상: `umph112/matchpost@738bcf64452d`

## 0. 문제

PC 화면에 D6~D14 규칙을 넣으면서 모바일을 함께 고치지 않았습니다.
같은 데이터를 두 화면이 **다른 규칙으로** 보여주는 상태입니다.

모바일은 별도 라우트가 아니라 **같은 페이지의 다른 뷰**입니다
(`AdvertiserShell` 이 `<main>` 에 `adv-mobile` / `adv-pc` 클래스를 붙임).
그래서 대부분 **모바일 분기 안의 마크업만** 고치면 됩니다 — 로직은 이미 공유됩니다.

**⚠️ 로직을 새로 만들지 마세요.** PC 분기가 읽는 값을 모바일 분기도 읽게 하는 것이 전부입니다.
값이 갈리면 두 화면이 다른 말을 합니다.

## 1. 캠페인 「게재뒤수정」 단계 (D13 B1)

```
src/lib/campaign-stages.ts        (이미 9단계 — 손대지 마)
모바일 딜시트 · 캠페인 카드의 단계 표시
```

PC 는 9단계(협의·수락·가이드·방문·원고·수정/컨펌·게재·**게재뒤수정**·정산)를 쓰는데,
모바일에 8단계로 하드코딩된 배열이 남아 있는지 확인하세요.

```bash
grep -rn "'정산'\]" src/app src/components   # 하드코딩된 단계 배열
grep -rn "게재뒤수정" src                     # 모바일 쪽에도 있어야 함
```

- 단계 목록은 `campaign-stages.ts` 에서 읽으세요. 배열을 두 곳에 두면 반드시 갈립니다
- 뺀 단계에 머문 사람은 `reindexStage` 로 다음 살아 있는 단계로 읽습니다 (PC 와 같은 함수)

## 2. 날짜 제안 카드 (D10 A6·A7)

```
src/components/messages/MessageBubble.tsx    (공유 컴포넌트일 것)
모바일 대화 화면
```

PC 대화에는 날짜 제안이 **말풍선이 아니라 카드**로 뜹니다. 모바일도 같아야 합니다 —
수락 여부가 딜시트로 이어지므로 눈에 띄어야 합니다.

```
min-width:214px · border:1px solid #FDE68A · background:#FFFBEB · radius:12px · padding:12px 14px
「날짜 제안」 10px/800 #B45309
날짜 16px/800 #17171B
부제 11px #92702A   (「열어두신 날짜예요」 / 「열어두신 날짜와 다른 날이에요」)
내 제안:   「상대가 수락하면 이 날짜로 확정돼요」 11px #B0B0BB
상대 제안: 「이 날짜로 수락」 (background:#17171B · radius:9px · min-height:36px)
수락됨:    「✓ 확정됨 · 딜시트에 반영」 background:#DCFCE7 color:#15803D
```

`MessageBubble` 이 공유 컴포넌트라면 이미 됐을 수 있습니다. **확인만** 하세요.

## 3. 취소 전파 (D10 A8)

```
모바일 딜시트 · 캠페인 목록 · 대시 목록
```

취소가 확정된 참여자는 모바일에서도 같아야 합니다:

| 자리 | 표시 |
| --- | --- |
| 딜시트 행 | 「취소」 배지 + 사유 · 단계 「진행 없음」 · 기한·방문·게재·메모 비움 · 페이 `—` · 세무 `—` · 정산 「해당 없음」 |
| 파생 숫자 | 모집 확정 · 집행 확정 · 팔로워 합계 · 게재 수 · 탭 카운트에서 **빠짐** |
| 대화 목록 | 배지 「취소 확정」 |

**행을 지우지 마세요.** 무슨 일이 있었는지가 기록입니다.

파생 숫자가 PC 와 같은 함수에서 나오는지 확인하세요. 모바일이 따로 세면 어긋납니다.

## 6. 상단바 · 이니셜 · 날짜 (D8)

```
src/components/TopBar.tsx
src/components/AdvertiserShell.tsx (모바일 분기)
```

- 상단바 **왼쪽은 서비스 이름 + 기간**, 오른쪽이 계정 영역. 계정명을 양쪽에 쓰지 마세요
- 아바타 이니셜은 `lib/initial.ts` — 「테스트 광고주」 → **「광」**
- 목록 시각은 `lib/date.ts` 의 `listTime()` — 오늘은 시각, 어제는 「어제」, 올해는 「7/21」

```bash
grep -n "toLocaleDateString" src/components/TopBar.tsx
grep -nP "[\x{1F300}-\x{1FAFF}\x{2699}]" src/components/TopBar.tsx
```

## 7. 「상세 내용은 PC 버전에서」 (D14 7절)

모바일에 억지로 담지 말고 요약 + 안내로 보낼 곳:

| 화면 | 모바일에서 |
| --- | --- |
| 광고주 딜시트 전체 표 | 요약 카드 + 「상세 내용은 PC 버전에서 확인해주세요」 |
| 팀 관리 · 팀원 업무 현황 | 같음 |
| 크레딧 원장 | 같음 |
| 정산 상세 표 | 같음 |

**⚠️ 그 화면의 행동은 앱에서 되어야 합니다** — 딜시트 표는 PC 로 보내도
대시 답장·정산 기록은 모바일에서 됩니다.

**⚠️ 인플루언서 화면에는 이 안내를 쓰지 마세요.** 앱이 주력 경로입니다.
인플루언서 딜시트는 자기 건 하나라 열이 적어 모바일에 다 들어갑니다 —
**내 일정과 진행 단계** 중심으로, 위에 다음 할 일 하나를 크게(「8/20까지 원고 제출」),
페이·미션·가이드는 펼쳐 보는 영역으로.

## 8. 모바일 가시성 — 옮길 때의 기준

PC 규칙을 그대로 축소하면 못 읽습니다. **무엇을 앞에 둘지**가 모바일의 설계입니다.

### 8-1. 크기 최소선

| 요소 | 최소 |
| --- | --- |
| 본문 글자 | 12px (PC 11.5px 를 그대로 쓰지 마세요) |
| 보조 설명 | 11px |
| 터치 대상 | **44px** — 버튼 · 탭 · 목록 행 · 전화 링크 |
| 배지 | 10px 이상. 9.5px 는 PC 전용 |

배지가 작아 안 읽히면 **글자를 줄이지 말고 배지를 빼세요.** 그 정보가 정말 필요한지부터 봅니다.

### 8-2. 한 화면에 하나만 강조

PC 는 배지 여러 개를 나란히 둘 수 있지만 모바일은 하나입니다. 우선순위:

```
1  지금 해야 할 것        미응답 · 미수 · 마감 임박
2  상태가 바뀐 것          취소 확정 · 담당자 교체 · 이관
3  분류                    방 종류(1:1 / 1:N) · 경로(초대 · 협업)
```

**1이 있으면 2·3을 숨기세요.** 취소된 건에 「1:N 참여 5명」을 함께 보여줄 이유가 없습니다.

### 8-3. 세 줄 안에 끝낸다

목록 행 하나는 **최대 세 줄**입니다.

```
1행  이름 · 시각
2행  마지막 대화 또는 핵심 값 (1줄 ellipsis)
3행  배지 하나 + 숫자
```

넘치면 3행을 버립니다. PC 의 「어디까지」 요약처럼 긴 문장은 **탭해서 들어간 뒤** 보여주세요.

### 8-4. 표는 카드로, 카드는 두 값만

딜시트·정산의 열을 카드로 옮길 때 **제목 + 값 두 개**까지입니다.

```
성수 델리카페 신메뉴 방문 리뷰
진행중 · 5/5명            1,150,000원
```

나머지 열(세무자료 · 메모 · 방문일)은 카드 안에 넣지 말고 상세로 보내세요.

### 8-5. 빈 상태에 다음 행동

PC 는 옆에 다른 카드가 있어 빈 목록이 견딜 만하지만, 모바일은 화면 전체가 빕니다.

```
「아직 대화가 없어요」  +  「인플루언서 찾기」 버튼
```

**안내문만 두지 마세요.** 이모지도 쓰지 마세요 — 32px 회색 lucide 아이콘입니다.

### 8-6. 색보다 위치

작은 화면에서 색 차이는 잘 안 보입니다.

- 급한 것은 **위로** 올리세요 (색만 빨갛게 하지 말고)
- 캘린더의 출처 구분은 **선**입니다 — 점선 = 직접 등록, 실선 = 시스템 생성
- 색 의미는 PC 와 같습니다: amber 브랜드·진행중 / blue 공개 오픈 전용 / green 완료 / red 지연

### 8-7. 하단 고정은 하나

입력창 · 확정 바 · 탭바가 동시에 뜨면 화면의 절반이 사라집니다.

- 대화 화면 = 입력창만 (탭바 숨김)
- 딜시트 = 확정 바만
- `padding-bottom: calc(N + env(safe-area-inset-bottom))` — 아이폰 홈 인디케이터

## 9. 확인

```bash
# 단계 배열이 한 곳에서만 나오는지

# 이니셜 · 날짜
grep -rn "name\[0\]\|charAt(0)" src/components
grep -rn "toLocaleDateString" src/components src/app | grep -v BlogAnalytics | grep -v admin/credits

# 이모지
grep -rnP "[\x{1F300}-\x{1FAFF}]" src/app src/components | grep -v "^\s*//"

# PC 안내가 인플루언서 화면에 없어야 함
grep -rn "PC 버전에서" src/app/\(dashboard\)/influencer   # 0 이어야 함
```

- [ ] 목록 아바타가 캠페인(파란 사각) / 개인(노란 원)으로 갈림
