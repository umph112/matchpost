# 1. 방문 로그에 시각 남기기

## 왜

`user_visit_log` 가 `(user_id, visited_on)` — **날짜 단위**입니다. 그래서 관리자 「오늘」의
트래픽을 시간대별로 못 그리고 14일 일별로 대신 쓰고 있습니다.

「저녁에 사람이 많은가」를 볼 수 없습니다. 지표 화면(D26)의 유입 묶음이 절반만 서 있습니다.

## 고칠 것

```sql
-- sql/migrations/00NN_visit_log_time.sql
alter table user_visit_log add column if not exists visited_at timestamptz;
create index if not exists user_visit_log_at_idx on user_visit_log (visited_at desc);
```

- 기록하는 곳에서 `visited_at = now()` 를 함께 남깁니다
- **`visited_on` 은 그대로 두세요** — 일별 집계(`visit-weekly` · `visit-monthly`)가 그것을 읽습니다
- 과거 행은 `visited_at` 이 null 입니다. 백필하지 마세요 — 없는 시각을 지어내는 셈입니다

## 화면

관리자 「오늘」의 트래픽을 **24시간 막대**로 바꿉니다. 단 **`visited_at` 이 있는 날만** —
데이터가 없는 구간은 「이 날짜 이전은 시간 정보가 없어요」로 비웁니다.

⚠️ 14일 일별 보기를 없애지 마세요. 탭으로 두 개(시간대 / 일별) 두는 편이 낫습니다.

# 2. 봇 시나리오 재실행

D23 이후 고친 것이 많습니다. **회귀가 없는지 전수 확인**입니다.

## 그동안 고친 것 — 이번에 확인할 자리

| 무엇 | 어느 시나리오에서 |
| --- | --- |
| 인플루언서 셸 (`layout.tsx`) | 11개 화면 전부 사이드바 있는지 |
| `.update()` 0행 → 서버액션 3개 | 딜시트 단계·세무·정산이 DB에 남는지 |
| 오픈 중복 방지 (`0096`) | 같은 날 두 번 등록이 막히는지 |
| 기간 오픈 (`date_end`) | 중간 날짜 검색에 잡히는지 |
| 오픈 협업 딜시트 (`/deals/[proposalId]`) | 양쪽에서 열리는지 |
| 인플루언서 단계 이동 (역할별) | 방문·원고·게재를 인플루언서가 넘기는지 |
| 「대시 보내기」 라벨 | 「협업 제안」이 남아 있지 않은지 |
| 버튼 두 줄 접힘 | PC·모바일 두 폭에서 |

## 실행 방식

- `headless: false` — 화면을 보면서
- 시나리오마다 스크린샷을 남기고 **레포에 커밋**하세요 (`docs/design/d30/screens/`)
- **막히면 우회하지 말고 멈추세요.** 사람도 같은 곳에서 막힙니다

## 새로 볼 것 — 아직 봇이 지나가지 않은 자리

| 시나리오 | 무엇 |
| --- | --- |
| 팀 운영 | 팀원 초대 → 가입 → 담당 캠페인 → 휴무 신청 → 대표 수락 + 대행자 |
| 이관 | 퇴사 예정 전환 → 퇴사자가 메모와 함께 이관 → 받는 사람 확인 |
| 관리자 | 「오늘」 큐 숫자 = 실제 건수 · 신고 종결 · 크레딧 지급 |
| 크레딧 | 대시 · 캠페인 등록에서 원장에 남는지 · 잔액 = 원장 합 |
| 공개 페이지 | `/campaigns/[id]` · `/opens/[id]` · `/advertiser/[id]` 로그아웃 상태에서 |

⚠️ **크레딧 원장 대조가 중요합니다** — 화면 잔액과 원장 합이 어긋나면 돈 문제입니다.

# 3. 관리자 광고관리

`cafe/AD-PRODUCTS.md` 에 상품 체계가 확정돼 있습니다. 그것을 화면으로 만듭니다.

## 3-1. 사이드바에 「광고관리」 그룹

```
광고관리
├─ 매치포스트 지면      (자체 광고 자리)
└─ 골프마니아클럽        (배너 · 게시글 양식 · 홍보 글 · 이벤트)
```

D26 셸의 사이드바에 그룹 하나를 더합니다. 화면이 없는 항목은 배지만 두고 눌리지 않게 —
D26에서 정한 규칙 그대로입니다.

## 3-2. 골프마니아클럽 — 무엇을 관리하나

**네이버 카페는 배너를 사람이 직접 올립니다.** 자동 게재가 없습니다.
그래서 이 화면의 핵심은 **「올렸음」 체크**입니다 — 그것이 없으면 판 것과 올린 것이 어긋납니다.

### 자리별 달력

```
가로축 = 월 (이번 달 · 다음 달 · 그다음)
세로축 = 자리 (A · B · C · D-0 · E-1~4 · 게시글 하단)

각 칸: 비었으면 회색 「비어 있음」
       팔렸으면 광고주명 + 상태 배지
```

상태 넷:
```
부킹      #F1F1F4 / #5C5C68   계약만 됨. 소재 미수령
소재 수령  #FEF3C7 / #B45309   받았으나 아직 안 올림
게재중    #DCFCE7 / #15803D   카페에 올렸음
종료      #F1F1F4 / #9A9AA5
```

⚠️ **「소재 수령」과 「게재중」을 반드시 갈라야 합니다.** 소재를 받고 올리는 걸 잊으면
그 기간이 통째로 빕니다. 광고주는 돈을 냈는데 노출이 없습니다.

### 건별 상세

| 항목 | 값 |
| --- | --- |
| 광고주 | 회사명 · 담당자 · 연락처 |
| 자리 | A · B · C … (`cafe/AD-PRODUCTS.md` 의 번호) |
| 기간 | 시작 – 종료 |
| 금액 | 계약 금액 · 입금 여부 |
| 소재 | 받은 파일 · 규격 확인 |
| **게재** | 올린 날짜 · 올린 사람 |
| 메모 | 협의 내용 |

### 상품별 탭

```
배너 · 게시글 양식 · 홍보 글 · 단독 게시판 · 이벤트
```

- **게시글 양식** — 한 줄 문구 + URL · 노출 기간 (소재가 없으니 「소재 수령」 상태 없음)
- **홍보 글** — 건수 · 작성 상태 (자리가 아니라 행위를 판다)
- **단독 게시판** — 운영 기간 · 게시판 링크
- **이벤트** — 투입 자산을 **체크로 기록**. 배너 자리를 함께 쓰면 달력에도 표시돼야 함

⚠️ 이벤트가 자리를 쓰면 그 자리는 그 기간에 **팔 수 없습니다.** 따로 관리하면 두 번 팝니다.

## 3-3. 문의는 화면에 없다

문의는 **전화·카카오톡**으로 받습니다. 폼을 만들지 않았으니 문의 수집 화면도 없습니다.
협의는 밖에서 하고 **결과만 여기 기록**합니다.

「문의 목록」 같은 것을 만들지 마세요 — 채울 것이 없습니다.

## 3-4. 공개 안내 페이지는 이번 범위 밖

`cafe/cafe-master.html` 이 자리 지도의 원본이고, 공개 안내 페이지는 아직 안 만들었습니다.
**관리자 화면부터** 하고 공개 페이지는 다음입니다 — 팔 것을 관리할 수 있어야 안내가 의미를 갖습니다.
