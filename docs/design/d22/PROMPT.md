━━━ A. 네이버·구글 검색 노출 ━━━

기준 하나만 지켜줘 — 「검색엔진이 보는 것 = 비회원이 보는 것」.
두 화면을 따로 만들지 마. 같은 페이지가 로그인 여부로 갈리게.
따로 만들면 어느 쪽이 참인지 갈리고 한쪽만 고치는 일이 생겨.

지금 robots·sitemap 이 0건이고 캠페인·오픈 상세에 metadata 가 없어.
색인돼도 검색 결과에 「매치포스트」만 나와.

A-2. 캠페인은 공개 — 회사가 내는 공고니까
  /campaigns/[id] 신규. 브랜드·제목·구분·채널·모집인원·기간·지역·미션 요약·대표 이미지.
  ⚠️ 참여자 명단·페이 금액은 빼. 페이는 협의 사항이고 공개되면 다음 협상의 기준선이 돼.

A-3. 오픈은 개인 일정이라 다르게
  /opens/[id] 신규. 날짜·지역·분야·채널 종류·페이대(구간)까지만.
  이름·채널 URL·팔로워·연락처·정확한 페이는 로그인 후.
  「이 사람이 8월 20일에 시간이 비어 있다」는 개인 신변 정보에 가까워.

  ⚠️ 오픈 등록에 「검색에 노출」 토글을 먼저 넣어줘 (기본 꺼짐, 0089).
     토글 없이 노출을 시작하면 이미 색인된 오픈을 나중에 빼기 어려워.

A-4. generateMetadata — 표에 title·description·og·robots 다 있어.
  ⚠️ URL 을 나중에 바꾸지 마. 색인된 뒤 경로를 바꾸면 처음부터 다시야.
     /campaigns/[id] · /opens/[id] 로 확정하자.

A-5. robots.ts · sitemap.ts
  로그인 뒤 화면은 전부 disallow.
  ⚠️ 지난 캠페인·오픈은 sitemap 에서 빼줘. 끝난 건이 검색에 남으면
     찾아온 사람이 「없는 건」을 봐. 페이지는 남기고(링크 깨지면 더 나쁨)
     「종료됐어요」 + 진행 중인 목록으로 안내해줘.

A-6. 신청은 캠페인·오픈이 쌓인 뒤에 할 거야. 지금은 준비만.

━━━ B. 초대 링크 자동 친구등록 — 먼저 확인해줘 ━━━

D13 §3 에서 source='invite' 를 「토큰 체계가 없어 제외」했는데
invite_token 이 이미 있는 걸 봤어. 그런데 확인해보니 다른 기능이야:

  invite_token          = 광고주가 자기 회사 팀원을 초대하는 토큰
  connections.'invite'  = 광고주가 인플루언서를 캠페인에 초대하는 것

⚠️ 팀원 초대 경로(api/signup/invite · api/team/accept)에 친구등록을 붙이지 마.
   같은 회사 사람인데 「친구등록된 인플루언서」가 돼버려.

그래서 이것만 확인해줘:
  grep -rn "campaign.*invite\|invite.*campaign" src/app/api src/lib
  grep -rn "join.*token\|campaign_invite" src sql

  · 캠페인 초대 링크가 있으면 → 참여 성공 지점에
    register_connection(..., 'invite', false) 를 붙여줘 (알림 없음 — 참여가 곧 의사 표시)
  · 없으면 → 이번 회차에 만들지 마. 공개 URL 체계·토큰 만료·중복 참여 처리가
    함께 필요해. 별도 건으로 보고해줘.
    'invite' 값은 source 제약에 남겨두고 목록 필터는 지금처럼 3개(전체·협업·직접) 유지.

판단이 필요하거나 문서와 실제 코드가 어긋나면 추측하지 말고 멈춰서 물어봐.
A 가 크니 A-2 · A-3 · A-4/5 로 끊어서 보고해줘.
끝나면 C절 grep 결과를 알려줘.
