```
1번 잘 됐어. 새 라우트로 간 판단도 맞아 — 한 파라미터가 두 가지를 뜻하면
소유 가드가 두 갈래로 섞여. viewerRole 기본값을 광고주 동작 그대로 둔 것도 맞아.

[승인] ②로 가줘 — 세 조작을 서버액션으로 옮기기

  왜 정책 추가(①)가 아니냐:
  · 같은 사고를 이번 세션에 세 번 겪었어 — .update() 0행을 if (!error) 로 성공 처리.
    정책을 늘리는 방식이면 다음에 또 같은 곳에서 뚫려
  · 광고주에게 「진행 칸만」 열어주려면 컬럼 단위 제한이 필요한데 RLS 로는 까다로워
  · 서버액션은 행 수를 확인하고 0이면 던질 수 있어

  범위는 세 개만 — advanceStage · toggleTaxDoc · setSettlement.
  다른 조작까지 옮기지 마.

  각 액션에서 반드시:
  · 당사자 확인 (광고주 = 그 캠페인 소속 · 인플루언서 = 그 proposal 본인)
  · UPDATE 후 **영향 행 수를 확인**하고 0이면 에러를 던져
  · 화면은 그 에러를 사용자에게 보여줘 — 조용히 넘어가지 마

  ⚠️ 캠페인 딜시트도 같은 코드라 함께 고쳐져. 그게 이 선택의 이점이야.
     고친 뒤 캠페인 딜시트에서도 단계 이동이 DB 에 남는지 확인해줘.

[정정] 기본 단계는 9개야. 「가이드」가 빠졌어.

  네가 넣은 8단계: 협의 · 수락 · 방문 · 원고 · 수정/컨펌 · 게재 · 게재뒤수정 · 정산
  맞는 9단계:     협의 · 수락 · **가이드** · 방문 · 원고 · 수정/컨펌 · 게재 · 게재뒤수정 · 정산

  오픈 협업에도 광고주가 가이드를 줘. 캠페인이 아니라서 가이드가 없는 게 아니야 —
  대시에서 「이렇게 찍어주세요」를 보내는 그 단계야.
  lib/campaign-stages.ts 의 전체 단계를 그대로 쓰면 돼.

  숫자를 지어내지 않은 판단(총예산·모집인원)은 맞아. 그건 그대로 둬.

[그다음] 로 findings 17번을 닫아줘. 원래 있던 결함이라는 기록은 남기고.

끝나면 이것만 확인해서 알려줘:
  · 광고주 세션에서 단계 이동 → DB 에 남나
  · 인플루언서 세션에서 단계 이동 → DB 에 남나
  · 캠페인 딜시트에서도 남나
  · 권한 없는 세션이 시도하면 에러가 화면에 뜨나
```
