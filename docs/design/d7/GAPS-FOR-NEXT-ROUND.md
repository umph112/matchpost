# D7 구현 후 남은 갭 — 다음에 확인해줄 것

D7-FIX-BUILD.md(1~8절) + D7-APPENDIX-LANDING-SIGNUP.md 전부 처리했다. 아래는 처리 과정에서
스펙만으로는 결정할 수 없거나, 이 앱의 실제 기능 범위를 넘어서서 이번엔 손대지 않은 부분들이다.

## 1. 소셜 로그인 3개 — 시각적으로만 존재, 실제로는 동작하지 않음

랜딩/로그인 우측 패널(`RoleLoginPanel.tsx`)에 카카오·네이버·Apple 버튼을 부록 스펙 그대로(색·문구)
넣었지만, 이 앱에는 어떤 OAuth 프로바이더도 연결돼 있지 않다(Supabase Auth에 provider 설정 자체가
없음). 버튼은 `disabled` + "준비 중이에요" 툴팁으로 눌러도 아무 일도 안 일어나게 해뒀다 — 동작하는
것처럼 보이는데 실제로 안 되는 것보다 낫다고 판단했다. 실제 소셜 로그인을 붙이려면 Supabase
Dashboard에서 각 provider의 client ID/secret 등록 + 콜백 라우트가 필요하다(이 라운드 범위 밖).

## 2. 랜딩 좌측 장식 달력 격자 — 생략

부록 3-4는 "구현이 부담되면 생략하고 검정 배경만 두세요"라고 명시적으로 허용했다. 지금은 검정
배경 + 헤드라인 + 3포인트만 있고 장식 격자는 없다. 필요하면 부록의 좌표·색상표대로 나중에 추가.

## 3. 인플루언서 모바일 가입 — "5단계"가 아니라 기존 단일 스크롤 폼 그대로

부록 4-3은 5개 화면으로 쪼개라고 했지만, "분야 칩은 지금 구현이 이미 맞습니다"라는 문구로 봤을 때
문서 작성 시점에도 완전히 새로 만들라는 뜻은 아니었다고 판단했다. 필드 구성·순서는 5단계 표와
동일하게 유지하되, 화면 전환 없이 한 번에 스크롤하는 기존 방식을 그대로 뒀다. 실제로 5단계 스와이프
UI가 필요하면 별도 스펙(전환 애니메이션, 뒤로가기 동작 등)이 있어야 한다.

## 4. 광고주 가입 — 사업자등록증을 진짜로 검증하지 않음

파일 업로드(`biz-docs` 비공개 버킷)와 승인/반려 시 자동 삭제(`/api/admin/biz-doc`), 30일 자동
삭제(`/api/cron/purge-attachments`)는 다 만들었다. **하지만 업로드된 파일이 진짜 사업자등록증인지
검증하는 로직은 없다** — 지금도 그랬듯 관리자가 "서류 보기"로 육안 확인 후 승인 버튼을 누르는
방식 그대로다. OCR·사업자등록번호 진위확인 API 연동은 범위 밖.

## 5. 팀 초대(가입 2단계) — 초대는 가는데, 초대장에 회사 이름이 없음

가입 2단계에서 입력한 이메일은 계정 생성 후 `inviteTeamMember()`로 실제 발송되지만(기존 D5
C2 로직 재사용), 이 시점에는 아직 `advertiser_profiles.company_name`이 막 저장된 직후라 초대
이메일 알림에 회사명이 정확히 반영되는지는 실제 가입 흐름으로 테스트하지 못했다 — 로직상으로는
문제없어야 하지만 실사용 확인 필요.

## 6. earnings 상태값 「완료」 vs 「결제완료」 — 병합하지 않음

D7 5-3은 "정산 쪽 용어(예정/미수/완료)와 맞추라"고 했는데, `earnings` 테이블의 status 값
자체가 어디서 어떻게 쓰이는지(정산 화면의 proposals 기반 예정/미수/완료 로직과는 별개 테이블)
충분히 추적하지 못했다. `파싱·집계 로직은 특히 위험`이라는 이 프로젝트의 원칙에 따라 상태값
자체는 건드리지 않고 라벨 하나만("예정 수입"→"예정 매출") 고쳤다. 두 상태값이 실제로 뭐가
다른지 확인해서 다음 라운드에서 정리할 것.

## 7. 인플루언서 메시지 페이지들 — InfluencerShell을 처음으로 대시(메시지)에 확장

D5 GAPS 5번에서 "InfluencerShell은 대시보드 한 곳에만 적용"이라고 남겼는데, 이번에 대시
목록·대화방 2개 라우트에도 새로 씌웠다(D7 3-1 PC 2단 레이아웃을 만들려면 `inf-pc` 클래스를 주는
조상이 필요했음). 나머지 7개 페이지(검색/오픈/알림/수익/프로필/채널분석/제안)는 여전히 기존
방식(TopBar 또는 자체 레이아웃)이라 그 페이지들로 이동하면 셸이 사라진다 — 전체 확장은 여전히
범위 밖.

## 8. `max-w-lg`·`toLocaleDateString`·용어 통일 — 감사 대상은 D7이 지정한 7개 파일만

D7 8절은 "다루지 못한 것" 7개 파일(DealSheet·campaigns/new·advertiser/dashboard·
BlogAnalyticsCard·DealConfirmBar·CampaignCalendar·influencer/dashboard)만 감사 대상으로
지정했고, 이번에 그 7개는 다 훑어서 이모지·`name[0]`을 고쳤다. **그런데 실제로 grep해보면
`max-w-lg`와 `toLocaleDateString('ko-KR')`을 쓰는 페이지가 그 밖에도 15개 이상 더 있다**
(알림함·제안함·오픈목록·프로필 등). D7이 명시적으로 지정한 범위가 아니라서 이번엔 안 건드렸지만,
같은 종류의 결함이니 다음 라운드에서 정리 대상으로 참고할 것.

## 9. 죽은 `/advertiser` 라우트, `admin/dashboard`의 "MatchPost" 텍스트

D7 4-7의 "7곳" 목록에는 없었지만, grep하면 `src/app/(dashboard)/advertiser/page.tsx`(로그인
후 role 체크만 하고 리다이렉트하는 것으로 보이는 레거시 라우트)와 `admin/dashboard/page.tsx`에
아직 "MatchPost" 텍스트가 남아있다. 지정 범위 밖이라 이번엔 손대지 않음.
