# D31 — 모바일 실사용 결함 (뒤로가기 · 탭 전환)

실제로 인플루언서 계정으로 모바일에서 쓰다가 나온 것. **둘 다 사람이 매번 겪는 자리다.**

---

# 1. 뒤로가기를 누르면 로그인 페이지로 간다

## 증상

화면을 보다가 뒤로가기를 누르면 갑자기 `/login` 으로 튄다. 로그인은 되어 있는 상태다.

## 짚어볼 원인

**세션 확인이 클라이언트에서 돌고, 복원되기 전에 리다이렉트가 걸린다.**

```
뒤로가기 → 페이지 복원 → useEffect 에서 getUser() → 아직 null → router.push('/login')
                                        ↓
                            (조금 뒤 세션이 복원되지만 이미 떠났다)
```

확인할 것:

```bash
grep -rn "router.push('/login')\|redirect('/login')" src/app src/components
grep -rn "getUser()" src/app/\(dashboard\)/influencer | head -20
```

- 클라이언트에서 `getUser()` 결과가 null 이면 즉시 보내는 곳이 있는지
- **로딩 상태를 구분하는지** — 「확인 중」과 「로그인 안 됨」은 다르다.
  구분 없이 null 을 「안 됨」으로 읽으면 첫 렌더마다 튄다
- 서버 컴포넌트(`layout.tsx`)에서 확인하면 이 문제가 없다. 왜 클라이언트에서 하는지 봐야 한다

⚠️ **어느 화면에서 튀는지 재현부터 하세요.** 특정 화면만이면 그 화면 문제이고,
전부면 셸이나 미들웨어 문제다.

## 고칠 방향

- 인증 확인은 **서버에서** (`layout.tsx` 의 `redirect()`)
- 클라이언트에서 해야 하면 **`loading` 상태를 반드시 거쳐서** — null 이라고 바로 보내지 말 것
- 뒤로가기 복원 시 세션을 다시 확인하지 않아도 되게 (서버 확인이면 자동)

# 2. 하단 탭을 눌러도 3초 뒤에 화면이 바뀐다

## 증상

모바일 하단 탭을 누르면 3초쯤 아무 반응이 없다가 화면이 바뀐다.

## 원인 (이미 측정된 것)

앞서 로딩 측정에서 나왔다 — **배포본 첫 그림이 2.5~3.5초**다:

| 화면 | 서버 응답 | 첫 그림 |
| --- | --- | --- |
| 광고주 대시보드 | 18ms | **3,296ms** |
| 인플루언서 찾기 | 8ms | **3,548ms** |
| 오픈 묶음 | 9ms | 2,588ms |

**서버는 빠르다.** 브라우저로 내려보내는 짐이 문제다 — JS 12개 742KB + CSS 121KB.
그리고 화면마다 클라이언트에서 데이터를 가져오는데, 그 전에 **아무것도 안 그려진다.**

## 지금 할 수 있는 것 — 큰 수술 없이

「완제품 후 일괄」로 미뤄둔 항목이지만, **탭 전환이 3초면 못 쓰는 수준**이다.
번들을 줄이는 일(큰 수술)과 별개로 **체감을 고치는 것**부터 하자.

| 무엇 | 효과 |
| --- | --- |
| 탭을 누른 즉시 **누른 표시**를 준다 (색·굵기 변화) | 「먹었나?」를 없앤다 |
| 이동할 화면에 **골격(skeleton)**을 먼저 그린다 | 흰 화면 3초가 사라진다 |
| Next `<Link prefetch>` 를 하단 탭에 | 다음 화면 코드를 미리 받아둔다 |
| 데이터를 **서버 컴포넌트로** 옮긴 화면부터 | 첫 그림에 이미 값이 있다 |

⚠️ **골격이 가장 효과가 크다.** 3초가 그대로여도 「뭔가 되고 있다」가 보이면 다르게 느껴진다.

## 어디부터

하단 탭 5개 화면만 — 홈 · 오픈 · 대시 · 캠페인 찾기 · 더보기.
그 다섯이 매번 오가는 자리다.

# 4. 상단바에 현재 위치 · 뒤로가기 (모바일)

## 왜

지금 모바일 상단바에 로고만 있어 **어느 화면인지 알 수 없다.** 그리고 화면마다
뒤로가기가 있는 곳과 없는 곳이 섞여 있다 — 없는 화면에서는 브라우저 뒤로가기를 쓰게 되고,
그것이 1절의 「로그인으로 튀는」 문제와 겹친다.

## 상단바 규격

```
[←]  로고  |  현재 화면 이름                        [계정]
```

| 자리 | 값 |
| --- | --- |
| 뒤로가기 | 왼쪽 끝 · **44 × 44px** 터치 영역 · lucide `ChevronLeft` 20px |
| 로고 | 마크만 (24px) — 이름은 폭을 먹는다 |
| 구분자 | `|` · `color:#EAEAEE` · `margin:0 9px` · 높이 14px |
| 현재 화면 | 13px/700 · `#17171B` · `letter-spacing:-0.01em` |
| 계정 | 오른쪽 끝 · 아바타 28px |

- 화면 이름은 하단 탭 라벨과 **같은 말**을 쓴다 (홈 · 오픈 · 대시 · 캠페인 찾기 · 더보기)
- 하위 화면은 그 화면의 제목 (「내 채널 분석」 · 「매출 관리」)

## 뒤로가기 규칙

**모든 화면에 뒤로가기를 둡니다.** 없으면 탭을 이동해서 다시 찾아가야 한다.

| 화면 | 뒤로가기가 가는 곳 |
| --- | --- |
| 하위 화면 (내 채널 분석 · 매출 관리 …) | **정해진 상위 화면** — 어디서 왔든 같은 곳 |
| 대화방 | 대시 목록 |
| 하단 탭 5개 | **직전에 있던 탭** |

마지막 줄이 핵심이다. 탭 화면에서 `router.back()` 을 쓰면 앱 밖으로 나가거나
엉뚱한 곳으로 간다. **직전 탭을 기억해두고 그리로 보내세요:**

```
찾기 → 홈 → [←] → 찾기        ✅
찾기 → 홈 → [←] → 앱 밖        ❌
```

- 셸에 「직전 탭」 하나만 담아두면 된다 (이력 전체가 아니라 하나)
- 앱을 열고 첫 화면이면 뒤로가기를 **감춘다** — 돌아갈 곳이 없다
- 하위 화면은 `back()` 을 쓰지 마세요. 어디서 왔는지에 따라 달라져 예측할 수 없다

# 5. 저장했는지 알 수 없다 (블로그 주소 등)

## 증상

인플루언서로 가입한 뒤 블로그 주소를 넣고 저장을 눌렀는데 **버튼이 그대로 있어**
됐는지 안 됐는지 모른다.

## 고칠 것 — 버튼이 상태를 말해야 한다

```
평소      「저장하기」        amber · 눌림
누른 직후  「저장 중…」        회색 · 안 눌림
성공      「저장했어요」 ✓     green 배경 · 2초 뒤 「저장하기」로 복귀
실패      「저장 실패」        red · 아래에 이유
```

- **성공 표시를 2초 두세요.** 즉시 원래대로 돌아가면 아무 일도 없었던 것처럼 보인다
- 값을 고치지 않았으면 버튼을 **회색으로 비활성** — 누를 이유가 없다
- 이미 D28 에서 「채널을 등록했어요」 카드를 넣었는데, **버튼 자체가 반응하지 않으면**
  그 카드를 못 본다 (화면 아래쪽에 있으면 더욱)

⚠️ 이 규칙을 **저장 버튼이 있는 모든 화면에** 적용하세요 — 프로필 · 설정 · 공개 프로필 ·
오픈 등록 · 캠페인 등록. 한 화면만 고치면 다음 화면에서 또 같은 것을 묻는다.

```bash
grep -rn "저장하기\|저장됐어요" src/app src/components
```

# 6. 날짜가 잘려 보인다 (오픈 등록)

## 증상

9월 28일을 골랐는데 **「09월 2」** 로 잘려 보인다.

## 원인 — 날짜 칸이 좁아졌다

D29 에서 날짜 줄을 **두 칸(시작일 · 종료일)** 으로 나눴다. 폭이 절반이 되면서
`input[type=date]` 의 기본 표시가 칸을 넘친다. 모바일에서 특히 좁다.

```
전    [ 날짜 ]                 한 칸 — 넉넉했다
후    [ 시작일 ] [ 종료일 ]     두 칸 — 각 칸이 좁다
```

⚠️ `overflow:hidden` 으로 잘리는 것이라 **글자만 줄여도 안 될 수 있다.**
브라우저 기본 날짜 위젯은 자기 최소 폭을 갖는다.

## 고칠 방향 — 셋 중 하나

| 안 | 방법 |
| --- | --- |
| **① 모바일에서 두 줄로** | 좁은 폭에서는 시작일·종료일을 세로로. `grid-cols-1 sm:grid-cols-2` |
| ② 칸 폭을 늘리고 글자를 줄임 | `min-width:0` + `font-size:13px` + `padding` 축소. 위젯 최소 폭에 걸릴 수 있다 |
| ③ 직접 만든 날짜 선택기 | 표시를 우리가 정한다. 범위가 크다 |

**①을 권합니다.** 모바일에서 날짜 두 개를 나란히 둘 이유가 없고, 세로로 두면
각 칸이 전체 폭을 써서 잘릴 일이 없다.

## 같은 것을 함께 볼 곳

날짜 칸이 좁은 자리가 또 있는지 봐야 한다:

```bash
grep -rn 'type="date"' src/app src/components
```

- 캠페인 등록의 기본 일정 (원고 · 수정/컨펌 · 게재 · 정산 — **4칸**)
- 결제일 변경 제안 모달
- 휴무 신청

⚠️ **캠페인 등록의 4칸이 가장 좁다.** 모바일에서 확인하세요.

# 7. PC 로 보는데 모바일 화면이 섞여 나온다

## 증상

PC 브라우저로 쓰는 중에 어떤 화면은 PC 로, 어떤 화면은 **모바일 폭 그대로** 나온다.

## 원인 — 셸이 안 붙은 화면이 남아 있다

D30 봇 점검에서 인플루언서 11개 화면에 셸을 붙였지만, **광고주 쪽과 공통 화면**은
아직 확인하지 않았다. `[.adv-pc_&]:` · `[.inf-pc_&]:` 변형은 셸의 `<main>` 이
그 클래스를 줄 때만 동작한다 — 조상이 없으면 죽은 코드다.

```bash
# 셸 밖에 있는 화면 찾기
grep -rln "max-w-lg mx-auto" src/app | sort

# 그 화면에 PC 변형이 있는지 (있는데 안 먹으면 셸이 없는 것)
grep -rln "\[.adv-pc_&\]:\|\[.inf-pc_&\]:" src/app | sort
```

## 확인할 곳

| 묶음 | 어디 |
| --- | --- |
| 공통 | `/day/[date]` · `/profile/[id]` · `/influencer/[id]` · `/advertiser/[id]` |
| 공개 | `/campaigns/[id]` · `/opens/[id]` · `/terms` · `/privacy` |
| 광고주 | 셸이 `advertiser/layout.tsx` 한 곳이라 괜찮을 것 — **확인만** |
| 인플루언서 | `influencer/layout.tsx` 신설로 해결됨 — **회귀 확인** |

⚠️ **공개 페이지는 셸이 없는 것이 맞다.** 로그인 없이 보는 화면이라 사이드바를 둘 수 없다.
다만 **본문 폭은 PC 에서 넓어져야** 한다 — `max-w-lg`(512px) 로 갇히면 안 된다.

## 화면은 세 종류다 — 판정 기준이 다르다

| 종류 | 예 | PC 기준 | 모바일 기준 |
| --- | --- | --- | --- |
| **쌍으로 있는 화면** | 인플루언서 홈 · 대시 · 광고주 딜시트 | 셸 + 넓은 본문 | 하단 탭 + 단일 컬럼 |
| **PC 만 있는 화면** | **광고주 일부 · 관리자 일부** — 딜시트 전체 표 · 팀 관리 · 업무 현황 · 크레딧 원장 · 관리자 지표·원장 | 정상 | 「상세 내용은 PC 버전에서 확인해주세요」 |
| **공개 화면** | `/campaigns/[id]` · `/opens/[id]` · `/advertiser/[id]` · 약관 | 셸 없음 · 본문 넓음 | 셸 없음 · 단일 컬럼 |

⚠️ **관리자도 모바일이 있다.** 프로토타입 `매치포스트 관리자 모바일.dc.html` 이 그것이다.
앱에서는 **알림 · 처리 대기 큐 · 신고 확인 · 회원 조회**를 한다 —
밖에서 급한 것을 놓치지 않는 것이 목적이다.
PC 로 보내는 것은 **표·달력·원장이 중심인 화면**뿐이다 (지표 · 크레딧 원장 · 정산 모니터).

⚠️ **인플루언서 화면은 PC 전용이 하나도 없다.** 인플루언서는 앱이 주력이라
전 화면이 모바일에서 제대로 나와야 한다. 인플루언서 화면에 「PC 버전에서 확인」이
뜨면 그것이 결함이다 — 주력 경로를 막는 것이다.

⚠️ **PC 만 있는 화면을 모바일에서 「깨졌다」고 판정하면 안 된다.** 그건 의도된 것이고,
안내 문구가 뜨는지를 봐야 한다. 반대로 안내도 없이 모바일 폭으로 억지로 나오면 그건 결함이다.

## ⚠️ 가장 흔한 증상 — 셸은 PC, 안쪽은 모바일

봇 화면에서 실제로 이렇게 보입니다: **테두리(사이드바·상단바)는 PC 인데 본문만 480px 에 갇혀 있음.**

셸이 없는 것이 아닙니다. 셸은 `adv-pc` / `inf-pc` 클래스를 주는데 **그 화면이 변형을 안 쓴** 것입니다.

```
있어야 하는 것    max-w-lg mx-auto px-4 [.adv-pc_&]:max-w-none [.adv-pc_&]:px-0
지금 그 화면       max-w-lg mx-auto px-4          ← 변형이 없다
```

찾는 법:

```bash
# 셸 안에 있으면서 PC 변형이 없는 화면
grep -rn "max-w-lg\|max-w-2xl" src/app/\(dashboard\) | grep -v "adv-pc\|inf-pc"
```

**세 가지가 다 원인일 수 있어 하나씩 갈라야 합니다:**

| 증상 | 원인 |
| --- | --- |
| 셸도 없고 본문도 좁다 | 레이아웃이 셸로 감싸지 않음 |
| **셸은 있는데 본문만 좁다** | **PC 변형이 없음 — 이게 지금 보이는 것** |
| 변형은 있는데 안 먹는다 | 셸이 그 클래스를 주지 않음 (조상이 다름) |

D8 · D26 에서 각각 고쳤는데 **화면이 늘 때마다 다시 빠집니다.** 화면마다 손으로 붙이는 방식이라
그렇습니다 — 셸 쪽에서 본문 폭을 정하는 구조로 바꾸는 것이 근본입니다.

## 공개 화면도 PC 규격이 있다 — 로그인 · 가입

셸이 없어서 폭 변형 대상에서 빠져 있었습니다. 그런데 **랜딩(`/`)에는 PC 규격이 있습니다** —
좌측 검정 패널 + 우측 460px 폼의 2단입니다 (`D7-APPENDIX-LANDING-SIGNUP.md`).

| 화면 | PC | 모바일 |

## 봇 점검 방식

먼저 **화면 목록을 세 종류로 분류한 표**를 만들고, 그 표를 기준으로 판정하세요.

```
PC 폭(1440) 순회
  쌍 화면 · PC 전용 → 셸 있음 · 본문 폭 512px 아님
  공개 화면        → 본문 폭 512px 아님 (셸은 없어도 됨)

모바일 폭(390) 순회
  쌍 화면   → 하단 탭 있음 · 가로 스크롤 없음
  PC 전용   → 「PC 버전에서 확인」 안내가 뜸 (광고주 화면만)
  인플루언서 → PC 전용이 하나도 없어야 함. 안내가 뜨면 실패
  관리자     → 알림·큐·신고·회원은 모바일에서 됨. 지표·원장만 PC 안내
  공개 화면 → 가로 스크롤 없음
```

**두 폭을 섞지 말고 각각 끝까지** 돌리세요. 섞으면 어느 폭에서 깨진 화면인지 알 수 없다.

⚠️ 분류표를 먼저 만들어 보고해 주세요. 어느 화면이 「PC 만」인지 제가 확인해야
잘못된 판정이 쌓이지 않습니다.
