# D29 — 오픈 협업의 딜시트 · 기간 오픈

대상: `umph112/matchpost@300b80d7b564`

두 건이 얽혀 있습니다. **기간 오픈이 안 만들어지면 D24 「오픈 묶음 보기」가 성립하지 않고,
오픈 협업에 딜시트가 없으면 그 화면에 담을 것도 없습니다.**

---

# 1. 오픈 대시로 성사된 협업에 딜시트가 없다

## 증상

봇 점검에서 확인됐습니다. 오픈에 대시가 와서 양쪽 확정까지 갔는데,
그 협업의 딜시트를 볼 곳이 없습니다.

## 원인

딜시트가 **캠페인 단위**로만 조회됩니다.

```
src/app/(dashboard)/advertiser/campaigns/[id]/page.tsx   ← 캠페인 id 로 들어감
```

오픈 대시로 만들어진 `proposals` 는 `campaign_id` 가 **null** 입니다
(캠페인이 없으니 당연합니다). 그래서 어느 캠페인 딜시트에도 안 잡힙니다.

## 고칠 것 — 딜시트의 단위를 협업(proposal)으로

```
캠페인 딜시트  = 그 캠페인의 proposals 를 모아 보는 것
오픈 딜시트    = proposal 하나짜리 딜시트
```

**단계는 캠페인 등록 때 정한 값이 원본**인데 오픈 협업에는 그것이 없습니다.
그러면 **기본 9단계**를 씁니다 (`lib/campaign-stages.ts` 의 전체 단계).

```
협의 · 수락 · 가이드 · 방문 · 원고 · 수정/컨펌 · 게재 · 게재뒤수정 · 정산
```

대시에서 「수정/컨펌 없이 진행」처럼 조정하면 그 협업만 단계가 줄어듭니다.

## 들어가는 길 — 이미 있는 두 화면에 링크만

| 누가 | 어디 | 무엇 |
| --- | --- | --- |
| 인플루언서 | `influencer/schedule/[id]` (오픈 묶음 보기) | 각 협업 카드의 「딜시트 열기 →」 |
| 광고주 | 대시 헤더 (개인 대화) | 「딜시트」 링크 |

새 화면을 만들지 마세요. 캠페인 딜시트가 `proposal_id` 로도 열리게 하면 됩니다.

```
/advertiser/campaigns/[id]           ← 지금 (캠페인)
/advertiser/deals/[proposalId]       ← 추가 (협업 하나)
```

또는 같은 라우트에서 분기하세요 — 어느 쪽이 코드가 덜 갈라지는지 보고 판단해 주세요.

⚠️ **한 곳만 고치면 안 됩니다.** 인플루언서 쪽에도 같은 화면이 필요합니다
(`influencer/proposals` 에서 진행 단계를 보는 자리).

# 2. 기간 오픈이 만들어지지 않는다

## 증상

「8월 28~29일」처럼 여러 날 오픈을 등록할 수 없습니다.

## 원인

`schedules.date_end` 를 **읽는 곳은 4곳, 쓰는 곳은 0곳**입니다.

```bash
grep -rn "date_end" src        # 읽기 4 · 쓰기 0
```

- 등록 폼(`influencer/schedule/page.tsx`)에 **종료일 입력칸이 없습니다**
- 검색(`advertiser/search`)도 `date` 만 봅니다 — 기간 오픈이 있어도 중간 날짜로는 안 잡힙니다

**D24 「오픈 묶음 보기」가 이 전제 위에 있습니다.** 「여수 1박 2일」이 그 예였는데,
지금은 그런 오픈을 만들 방법이 없습니다.

## 고칠 것

### 2-1. 등록 폼에 기간

```
날짜 줄을 두 칸으로:
  [ 시작일 ]  [ 종료일 · 선택 ]
  height:46px · radius:11px · 1fr 1fr gap:12px
```

- 종료일을 비우면 **하루 오픈** (`date_end = null` 또는 `= date`)
- 종료일이 시작일보다 앞이면 막기
- 아래 안내: 「여러 날에 걸친 일정이면 종료일을 넣어주세요. 하루면 비워두면 됩니다.」

⚠️ **중복 검사도 기간을 봐야 합니다.** 지금 `0096` 유니크 인덱스는 `(influencer_id, date)`
하나짜리입니다. 기간 오픈이 기존 오픈과 겹치는지 확인하는 것은 다른 문제입니다 —
**이번에는 시작일 중복만 막고**, 기간 겹침은 별도 건으로 두세요.
지금 막으려 들면 「하루 오픈이 기간 오픈 안에 들어가도 되나」를 정해야 합니다.

### 2-2. 검색이 기간을 잡게

```
현재  .eq('date', 고른날짜)
정답  고른 날짜가 [date, date_end] 안에 들면 잡힌다
      .lte('date', 고른날짜).or(`date_end.gte.${고른날짜},date_end.is.null`)
```

⚠️ `date_end` 가 null 인 하루 오픈도 잡혀야 합니다. `or` 절에서 빠뜨리기 쉽습니다.

기간 검색(시작~끝)일 때는 **겹치면 잡습니다** — 완전히 포함될 필요가 없습니다.
「8/25~8/30 을 찾는데 8/28~8/29 오픈」은 결과에 나와야 합니다.

### 2-3. 화면 표기

| 곳 | 하루 | 기간 |
| --- | --- | --- |
| 목록 · 카드 | `8/28 (금)` | `8/28 (금) – 8/29 (토)` |
| 달력 | 그날 하나 | **시작~끝 전체에 표시** |
| 공개 페이지 (`/opens/[id]`) | 같음 | 같음 |

⚠️ 달력에서 기간 오픈이 시작일에만 뜨면, 광고주가 중간 날짜를 보다가 놓칩니다.

# 3. 순서

**2번을 먼저 하세요.** 기간 오픈을 만들 수 있어야 1번의 「오픈 묶음」에 담을 것이 생깁니다.
하루 오픈으로도 1번을 검사할 수는 있지만, D24 화면이 전제하는 상황은 기간 오픈입니다.

# 4. 확인

```bash
# 기간 오픈
grep -n "date_end" src/app/\(dashboard\)/influencer/schedule/page.tsx   # 쓰기 있어야 함
grep -n "date_end" src/app/\(dashboard\)/advertiser/search/page.tsx     # 검색이 봐야 함

# 오픈 협업 딜시트
grep -rn "campaign_id.*null\|proposalId" src/app/\(dashboard\)/advertiser | head
ls src/app/\(dashboard\)/advertiser/deals 2>/dev/null   # 새 라우트로 갔다면
```

브라우저:
- [ ] 오픈 등록에 종료일 칸이 있고, 비우면 하루로 저장됨
- [ ] 종료일이 시작일보다 앞이면 막힘
- [ ] 기간 오픈이 **중간 날짜 검색에도** 잡힘
- [ ] 하루 오픈(`date_end` null)이 검색에서 안 사라짐
- [ ] 달력에서 기간 오픈이 시작~끝 전체에 표시됨
- [ ] 오픈 대시로 성사된 협업의 딜시트가 열림 (9단계)
- [ ] 그 딜시트가 인플루언서·광고주 양쪽에서 보임
- [ ] 「오픈 묶음 보기」에서 각 협업의 딜시트로 갈 수 있음
