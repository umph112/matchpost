```
handoff_D33 폴더를 docs/design/d33/ 에 넣고 커밋해줘.
그다음 D33-WIDTH-SWEEP.md 대로 해줘. 테스트가 막히는 자리야 —
PC 로 봐도 본문이 모바일 폭으로 나와서 끝까지 못 봐.

⚠️ 이 문제를 세 번 고쳤고 세 번 다시 나왔어 (D8 · D16 · D26).
   매번 「발견된 화면」만 고쳤기 때문이야. 이번엔 기계로 세고 전수로 처리해줘.

[먼저 알아둘 것] 두 가지를 갈라야 해. 이게 세 번 다시 나온 이유야.

  ① 폭   — 구성은 같은데 PC 에서 512px 에 갇힘 → 셸이 폭을 정하면 끝
  ② 구성 — PC 는 2단·표, 모바일은 세로 쌓기·카드. PC 레이아웃 자체가 없음 → 화면마다 설계 필요

  ②는 셸이 못 해줘. 레포에 정상 사례가 있어 — MyCampaignsList 는 PC 표와 모바일 카드를
  둘 다 그려두고 .adv-pc 로 한쪽만 보이게 해. 그게 맞는 방식이야.

  지난 회차들은 ②를 ①로 착각해서 변형 한 줄만 붙였어.
  폭만 풀면 모바일용 세로 배치가 1440px 로 늘어나 「한 줄에 항목 하나」가
  화면 끝까지 뻗어 — 갇힌 것보다 더 나빠.

[1단계] 먼저 세줘. 코드는 아직 건드리지 말고.
  문서 2절의 grep 네 개를 돌려서 셋으로 갈라 보고해줘 —
    A. 폭만 문제 (최상위 max-w-lg + 내부에 PC 구성 있음)   N개
    B. PC 구성이 아예 없음                                  N개 ← 화면 이름까지
    C. 정상                                                 N개

  ⚠️ grep 만으로는 A·B 가 정확히 안 갈려. .adv-pc 조건이 한두 곳 있어도
     실제 PC 구성이 없을 수 있어. 애매한 건 파일을 열어 확인하고,
     그래도 판단이 안 서면 「확인 필요」로 따로 적어줘. 추측해서 A 로 넣지 마.

  이번 회차에는 A 만 처리해. B 는 목록을 받고 나서 화면별로 구성을 정할게.

  ⚠️ B 목록은 역할별로 나눠줘 (인플루언서 / 광고주 / 관리자). 처리 방향이 반대야 —

    인플루언서 — 모바일에서 전부 돼야 해. 모바일 구성은 이미 있으니 PC 구성을 새로 만들어.
                「PC 에서 확인해주세요」를 쓰면 안 돼. 앱이 주력 경로인데 그걸 막는 거야
    광고주     — 모바일은 확인·응대만. 상세 화면은 「상세 내용은 PC 버전에서 확인해주세요」로
                보내도 돼. 단 읽기만 보내고 행동(대시 답장 · 정산 기록)은 모바일에서 되게 둬
    관리자     — PC 구성만. 모바일 구성을 만들지 마 (알림 확인만 모바일)

  ⚠️ 공개 화면도 세줘 — src/app 직속(login · signup · campaigns/[id] · opens/[id] ·
  advertiser/[id] · influencer/[id] · terms · privacy). 셸이 없어서 지난 회차들이 전부 빠뜨렸어.

[2단계] A 부류 고치는 방법 — 화면마다 손으로 붙이지 마.
  세 번 다시 나온 이유가 그거야. 셸이 폭을 정하게 해줘.

    지금   셸(폭 무제한) → 화면(max-w-lg 로 자기를 좁힘) → PC 변형으로 되돌림
    정답   셸(폭 결정) → 화면(폭에 관여하지 않음)

  · 셸의 <main> 이 PC 에서 max-w-none px-7, 모바일에서 max-w-lg mx-auto px-4
  · 각 화면에서 최상위 컨테이너의 max-w-* · mx-auto · px-* 를 걷어내
  · 화면 안쪽의 max-w-*(카드 폭 제한 등)는 그대로 둬 — 최상위만 대상이야
  · 그러면 새 화면을 만들 때 아무것도 안 해도 양쪽이 맞아

  ⚠️ 셸을 고치면 모든 화면이 한꺼번에 바뀌어.
     고친 뒤 PC(1440) · 모바일(390) 두 폭에서 전 화면을 캡처해 커밋해줘.
     내가 눈으로 확인할게.

[3단계] 역할별로 다른 것
  · 광고주 — PC 주력. 전 화면 PC 변형
  · 인플루언서 — 앱이 주력이지만 PC 변형은 필요해.
    「앱이 주력」은 PC 를 막는다는 뜻이 아니야. PC 로 열었을 때 512px 에 갇히면 결함이야
  · 관리자 — PC 전용
  · 공개 — login·signup 은 랜딩과 같은 2단(좌 검정 / 우 460px),
    읽는 화면(campaigns/[id] · opens/[id] · terms · privacy)은 가운데 720px,
    /pending 은 좁은 게 맞아 (안내 한 장)

[4단계] 봇도 두 폭으로
  지금 한 폭으로 섞여 돌아서 「PC 인데 모바일 화면」을 못 잡아.
  프로젝트를 pc(1440x900) · mobile(390x844) 둘로 나누고
  같은 시나리오를 각각 끝까지 돌려줘. 중간에 폭을 바꾸지 마.

  각 화면에서: PC 본문 폭이 512 가 아닌지 · 모바일에 가로 스크롤이 없는지 ·
  사이드바(PC) · 하단 탭(모바일)이 있는지.

  ⚠️ MyCampaignsList 처럼 PC 표와 모바일 카드를 둘 다 그려두고 CSS 로 숨기는 건 정상이야.
     고치지 말고, 봇이 숨은 쪽을 집지 않게만 해줘 (filter({ visible: true })).

  ⚠️ PC 에서 「한 줄에 항목 하나」가 화면 끝까지 뻗는 화면도 적어줘 — 그게 B 부류야.

1단계 개수부터 보고해줘. 그 숫자를 보고 2단계 범위를 정하자.
판단이 필요하거나 문서와 실제 코드가 어긋나면 추측하지 말고 멈춰서 물어봐.
```
