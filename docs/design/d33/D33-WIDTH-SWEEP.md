# D33 — PC · 모바일 폭 전수 정리

테스트가 막히는 자리입니다. PC 로 봐도 본문이 모바일 폭으로 나와 끝까지 못 봅니다.

⚠️ 이 문제를 **세 번 고쳤고 세 번 다시 나왔습니다** (D8 · D16 · D26).
매번 「발견된 화면」만 고쳤기 때문입니다. 이번에는 **기계로 세고 전수로 처리**합니다.

---

# 0. ⚠️ 두 가지를 갈라야 한다 — 폭과 구성

세 번 다시 나온 이유가 이것입니다. **폭 문제로 착각하고 변형 한 줄만 붙였는데,
실제로는 PC 레이아웃이 없던 화면**이었습니다.

| | 무엇 | 어떻게 |
| --- | --- | --- |
| **① 폭** | 구성은 같은데 PC 에서 512px 에 갇힘 | **셸이 폭을 정하면 끝** |
| **② 구성** | PC 는 2단·표, 모바일은 세로 쌓기·카드 — PC 레이아웃 자체가 없음 | **화면마다 설계 필요** |

②는 셸이 못 해줍니다. 지금 레포에 **정상 사례가 있습니다** — `MyCampaignsList` 는
PC 표(170행)와 모바일 카드(274행)를 **둘 다 그려두고** `.adv-pc` 로 한쪽만 보이게 합니다.
그게 맞는 방식입니다.

## 그래서 1단계에서 셋으로 갈라 세세요

| 분류 | 판정 | 이번에 |
| --- | --- | --- |
| **A. 폭만** | 최상위에 `max-w-lg`, 내부에 PC 구성 있음 | 셸 정리로 자동 해결 |
| **B. 구성 없음** | PC 용 마크업이 아예 없음 (`.adv-pc`/`.inf-pc` 조건 0건) | **화면별로 목록 뽑아 보고** |
| **C. 정상** | 두 구성이 다 있고 변형도 있음 | 손대지 않음 |

⚠️ **B 를 A 로 처리하면 안 됩니다.** 폭만 풀면 모바일용 세로 배치가 1440px 로 늘어나
「한 줄에 항목 하나」가 화면 끝까지 뻗습니다 — 갇힌 것보다 더 나쁩니다.

B 는 목록을 받은 뒤 화면별로 어떤 구성으로 갈지 정하겠습니다. 이번 회차에는 **A 만** 처리하세요.

---

# 1. 원인 (A 부류) — 화면이 스스로 폭을 좁힌다

셸은 `.adv-pc` / `.inf-pc` 클래스를 정상적으로 줍니다. 문제는 각 화면이 이렇게 시작하는 것입니다:

```
max-w-lg mx-auto px-4        ← 본문을 512px 로 제한
```

모바일을 먼저 만들었기 때문입니다. PC 는 나중에 그 제한을 푸는 변형을 덧붙이는 방식이었습니다:

```
max-w-lg mx-auto px-4 [.adv-pc_&]:max-w-none [.adv-pc_&]:px-0
```

**변형을 안 붙인 화면은 PC 에서도 512px 에 갇힙니다.** 테두리(셸)는 PC 인데 안쪽만 모바일인 그 증상입니다.

---

# 2. 먼저 세기 — 문서를 쓰기 전에 목록을 만든다

```bash
# ① 로그인 뒤 화면 전체
find src/app/\(dashboard\) -name page.tsx | sort

# ② 폭을 스스로 좁히는 화면
grep -rln "max-w-lg\|max-w-md\|max-w-sm\|max-w-xl\|max-w-2xl" src/app/\(dashboard\)

# ③ 그중 PC 변형이 있는 화면
grep -rln "adv-pc_&\]:max-w\|inf-pc_&\]:max-w" src/app/\(dashboard\)

# ④ PC 구성이 아예 없는 화면 (B 부류 판정)
grep -rLn "adv-pc_&\]:\|inf-pc_&\]:" $(grep -rln "max-w-lg" src/app/\(dashboard\))
```

**개수를 먼저 보고해 주세요** — 전체 N개 · **A 부류 N개 · B 부류 N개 · C 부류 N개**.
그 숫자가 검산표입니다.

B 부류는 **화면 이름까지 적어 주세요.** 그것이 다음 회차의 작업 목록입니다.

⚠️ grep 만으로는 A·B 가 정확히 안 갈립니다 — `.adv-pc` 조건이 한두 곳 있어도
실제 PC 구성이 없을 수 있습니다. **애매한 것은 파일을 열어 확인**하고, 그래도 판단이 안 서면
그 화면을 「확인 필요」로 따로 적어 주세요. 추측해서 A 로 넣지 마세요.

⚠️ 공개 화면도 세세요 — `src/app/` 직속(`login` · `signup` · `campaigns/[id]` · `opens/[id]` ·
`advertiser/[id]` · `influencer/[id]` · `terms` · `privacy`). 셸이 없어 지난 회차들이 전부 빠뜨렸습니다.

# 3. 역할별로 다르게 처리한다

| 역할 | PC | 모바일 | 이번에 |
| --- | --- | --- | --- |
| **광고주** | **주력** | 확인·응대 | 전 화면에 PC 변형 |
| **인플루언서** | 보조 (앱이 주력) | **주력** | 전 화면에 PC 변형 (PC 로 와도 갇히면 안 됨) |
| **관리자** | **PC 전용** | 알림 확인만 | 전 화면 PC 폭 |
| **공개** | 랜딩 규격 | 그대로 | 아래 3절 |

⚠️ 인플루언서도 **PC 변형이 필요합니다.** 앱이 주력이라는 것은 「PC 를 막는다」가 아닙니다 —
PC 로 열었을 때 512px 에 갇히면 그것이 결함입니다.

## B 부류(PC 구성 없음)를 역할에 따라 다르게 처리한다

방향이 **반대**입니다. 만들 것과 안 만들 것이 역할로 갈립니다.

| 역할 | 모바일에서 | B 부류를 어떻게 |
| --- | --- | --- |
| **인플루언서** | **전부 된다** | 모바일 구성이 이미 있으니 **PC 구성을 새로 만든다** |
| **광고주** | 확인·응대만 | PC 구성을 만들고, 모바일은 **「상세 내용은 PC 버전에서 확인해주세요」로 보내도 된다** |
| **관리자** | 알림 확인만 | PC 구성만. 모바일 구성을 만들지 않는다 |

**인플루언서 화면에는 「PC 에서 확인해주세요」를 쓰지 마세요** — 앱이 주력 경로인데
그걸 막는 것이 됩니다. 모바일에 전 기능이 있어야 합니다.

**광고주·관리자는 반대입니다.** 좁은 화면에 억지로 담아 못 읽게 만드는 것보다
PC 로 보내는 것이 낫습니다. 다만 **읽기만 보내고 그 화면의 행동(대시 답장 · 정산 기록)은
모바일에서 되게** 두세요.

| 모바일에서 PC 로 보내도 되는 것 (광고주) | 모바일에서 반드시 되어야 하는 것 |
| --- | --- |
| 딜시트 전체 표 · 팀 관리 · 업무 현황 · 크레딧 원장 · 정산 상세 | 알림 · 대시 답장 · 진행 현황 · 캠페인 열기 · 대시 보내기 |

⚠️ 그래서 B 부류 목록을 받을 때 **역할별로 나눠 주세요.** 인플루언서 B 는 전부 만들어야 하고,
광고주·관리자 B 는 「만들 것 / 보낼 것」을 제가 정하겠습니다.

# 5. A 부류 고치는 방법 — 화면마다 손으로 붙이지 마세요

세 번 다시 나온 이유가 그것입니다. **셸이 폭을 정하게** 하세요.

```
지금   셸(폭 무제한) → 화면(max-w-lg 로 자기를 좁힘) → PC 변형으로 되돌림
정답   셸(폭 결정) → 화면(폭에 관여하지 않음)
```

- 셸의 `<main>` 이 PC 에서 `max-w-none px-7`, 모바일에서 `max-w-lg mx-auto px-4` 를 갖습니다
- **각 화면에서 `max-w-*` · `mx-auto` · `px-*` 를 걷어냅니다**
- 그러면 새 화면을 만들 때 아무것도 안 해도 양쪽이 맞습니다

⚠️ 화면 안쪽의 `max-w-*`(카드 폭 제한 등)는 그대로 두세요. **최상위 컨테이너만** 대상입니다.

⚠️ 셸을 고치면 **모든 화면이 한꺼번에 바뀝니다.** 고친 뒤 PC · 모바일 두 폭에서
전 화면을 캡처해 커밋해 주세요 — 눈으로 확인해야 합니다.

---

# 6. 테스트도 두 폭으로

지금 봇이 한 폭으로 섞여 돌아 「PC 인데 모바일 화면」을 못 잡습니다.

```
프로젝트 둘 — pc(1440x900) · mobile(390x844)
같은 시나리오를 각각 끝까지. 중간에 폭을 바꾸지 않는다.
```

각 화면에서 확인할 것:

- PC 에서 본문이 **512px 가 아닌지** (`getBoundingClientRect().width`)
- 모바일에서 가로 스크롤이 생기지 않는지
- 사이드바(PC) · 하단 탭(모바일)이 있는지

⚠️ 화면 하나에 PC 표와 모바일 카드를 둘 다 그려두고 CSS 로 숨기는 것은 **정상**입니다
(`MyCampaignsList`). 고치지 말고, 봇이 숨은 쪽을 집지 않게만 하세요(`filter({ visible: true })`).

⚠️ **PC 에서 「한 줄에 항목 하나」가 화면 끝까지 뻗는 화면**도 적어 주세요.
폭은 풀렸는데 구성이 모바일인 B 부류입니다.
