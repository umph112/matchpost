# 관리자 액션 전수 — 프로토타입 ↔ 레포 대조 (2026-08-22)

관리자가 다뤄야 하는 것을 **양쪽 콘솔에서 발생하는 것** 기준으로 전수 조사하고,
레포에 처리 경로가 있는지 대조했다.

⚠️ 관리자 구현 지시서를 D9 이후 한 번도 만들지 않았다. 그래서 레포는 화면 6개에
「← 뒤로」로만 이어진 상태다 (**사이드바가 없다**).

# 6-1. ⚠️ 자동 배치 13개 — 관리자 화면에 하나도 없다

`src/app/api/` 를 전수 열어보니 배치 라우트가 **13개** 있다. 전부 `requireCronOrAdmin` 로
보호돼 있고, 관리자가 **수동 실행할 수 있게** 만들어져 있다. 그런데 부를 화면이 없다.

| 라우트 | 무엇을 하나 | 관리자가 알아야 할 것 |
| --- | --- | --- |
| `admin/batch/payment-reminders` | 정산 지연 알림 (매일 1회) | 오늘 몇 건 보냈나 |
| `admin/batch/settlement-reminder` | 정산 예정일 알림 | |
| `admin/batch/report-autoclose` | 신고 자동 종결 | 무엇이 자동 종결됐나 |
| `admin/batch/sanction-recalc` | 제재 단계 재계산 | 누가 단계가 바뀌었나 |
| `admin/batch/trust-score-recalc` | **신뢰 점수 재계산** | ⚠️ 이 지표가 어디 쓰이는지 화면에 없다 |
| `admin/batch/cancellation-autoconfirm` | 취소 요청 자동 확정 | |
| `admin/batch/cancellation-count-reset` | 취소 누적 초기화 | 3회 규칙과 연결 |
| `admin/batch/dormant-decay` | **휴면 처리** | 누가 휴면이 되나 |
| `admin/batch/comeback` | **복귀 처리** | |
| `admin/batch/visit-weekly` · `visit-monthly` | **방문 집계** | 지표 화면의 원본 |
| `cron/blog-analytics` | 블로그 수집 (밤 10시 · D25) | 실패 건 |
| `cron/purge-attachments` | 첨부 7일 삭제 | 삭제 건수 |

**「데이터 운영」 화면의 실체가 이것이다.** 프로토타입에 항목만 있고 내용이 비어 있었는데,
실제로는 이 13개의 **마지막 실행 시각 · 결과 · 수동 실행 버튼**이 들어가야 한다.

⚠️ 세 기능은 **정책이 정해진 적이 없다** — 화면을 만들기 전에 정해야 한다:

| 기능 | 정해진 것 |
| --- | --- |
| `trust_score` | **관리자만 본다.** 제재 판정에 쓴다 — 지연율 + 약속 이행률 + 무단 변경률. 회원 화면에 노출 안 함 |
| `dormant-decay` (휴면) | **60일.** 53일에 예고 메일 → 60일 휴면 → 1회는 로그인으로 자동 해제 → 2회부터 관리자 확인 |
| `visits` (방문 집계) | **전 항목을 본다** (아래 지표 화면) |

### 지표 화면 — 전 항목

관리자는 사이트에서 일어나는 모든 것을 본다.

| 묶음 | 항목 |
| --- | --- |
| 유입 | 방문자 수 (일·주·월) · 화면별 방문 · 신규 가입 (광고주 / 인플루언서) |
| 공급 | 캠페인 등록 수 · 오픈 등록 수 · 진행중 캠페인 |
| 거래 | 대시 발송 수 · **협업 성사 수** · 성사 전환율 (대시 → 확정) |
| 돈 | 집행 금액 합계 · 미수 금액·건수 · 크레딧 사용·적립 |
| 유지 | 활성 사용자 (주·월) · 휴면 · 복귀 |

⚠️ 숫자는 전부 배치가 쌓은 집계에서 파생시킨다 (`visit-weekly` · `visit-monthly`).
화면에서 계산하면 볼 때마다 값이 달라진다.

# 7-1. 휴면 해제 요청 — 관리자 화면에 새로 필요

2회 이상 휴면된 계정이 돌아오면 자동 해제되지 않고 **요청이 관리자에게 쌓인다.**

| 화면 | 담을 것 |
| --- | --- |
| 「오늘」 큐 | 「휴면 해제 요청 N건」 |
| 회원 화면 | 상태 필터에 **휴면** 추가 · 해제 이력 (몇 번째인지) |
| 해제 동작 | 사유를 남기고 해제. `dormant_releases` 에 기록 |

⚠️ 진행 중인 협업이 있는 계정은 애초에 휴면으로 바뀌지 않는다 —
딜시트가 살아 있는 계정을 잠그면 정산이 막힌다. 배치에 그 조건이 있는지 확인해야 한다.

# 8. 그래서 화면 순서

**「오늘」이 먼저다.** 위 28개 중 매일 손이 가는 것만 큐로 모으는 화면이고,
그게 없으면 관리자가 어디를 봐야 하는지 알 수 없다.

| 순서 | 화면 | 담는 것 |
| --- | --- | --- |
| **1** | **셸 + 오늘** | 사이드바 12항목 + 처리 대기 큐 (신고 N · 정산 지연 N · 사업자 확인 N · 수집 실패 N) |
| **2** | 정산 모니터 | 2절 전부. 미수 판정을 `settlementDateOf()` 로 |
| **3** | 캠페인 · 딜시트 / 오픈 | 5절 조회 |
| **4** | 시스템 상태 · 데이터 운영 · 지표 | 6절 |
| **5** | 지면 · 제휴 | 7절 (후순위) |

이미 있는 화면(신고 · 크레딧 · 회원)은 **셸에 얹기만** 한다. 다시 만들지 않는다.

# 9. 셸 + 「오늘」 구현 스펙 (1단계)

프로토타입: `admin-pc.dc.html` (동봉 · 브라우저에서 바로 열림)

## 9-1. 셸

```
바깥  min-width:1360px · display:flex
사이드바 width:236px · flex-shrink:0 · background:#fff
        border-right:1px solid #EAEAEE
        position:sticky · top:0 · height:100vh
        display:flex · flex-direction:column
브랜드  height:64px · padding:0 20px · border-bottom:1px solid #F1F1F4
        로고 24px + MATCH·POST — 누르면 「오늘」로
본문    padding:20px 28px 40px · display:flex · flex-direction:column · gap:14px
```

⚠️ **간격은 14px 하나다.** 20·18·16 을 섞지 않는다 (`CLAUDE.md` 고정 규칙).

## 9-2. 사이드바 12항목 · 4그룹

```
오늘
────
신고 접수      배지 red
정산 모니터    배지
크레딧
크레딧 정책
────
회원          배지
캠페인 · 딜시트
오픈
────
시스템 상태    배지
데이터 운영    배지
지면 · 제휴
지표
```

```
항목  display:flex · align-items:center · gap:10px
      padding:9px 10px · border-radius:8px · font-size:13.5px
      선택   background:#FEF3C7 · color:#B45309 · font-weight:700
      미선택 color:#5C5C68 · font-weight:600
배지  margin-left:auto · 10.5px/700 · radius:20px · padding:1px 6px
      신고  background:#FEE2E2 · color:#DC2626
      그 외 background:#F1F1F4 · color:#7C7C88
구분선 그룹 사이
```

⚠️ **배지 숫자를 하드코딩하지 마라.** 각 화면의 원본 배열에서 파생시킨다.
프로토타입 주석에 「모든 숫자는 이 배열에서 파생시킨다. 하드코딩 금지」가 적혀 있다.

## 9-3. 「오늘」 — 처리 대기 큐 4칸

```
grid-template-columns: repeat(4,1fr) · gap:14px
카드 background:#fff · border-radius:14px · padding:15px 17px 16px · cursor:pointer
     border:1px solid  (급한 것은 #FECACA + background:#FEF2F2)
```

| 칸 | 내용 | 원본 |
| --- | --- | --- |
| 미입금 신고 | N건 · 「3일 초과 · 운영 확인 단계」 | `reports` (미입금 유형) |
| 사업자 확인 | N건 · 「가입 승인 대기」 | `advertiser_profiles.biz_doc_url` 미승인 |
| 결제 지연 | N건 · 「예정일 지난 미수 건」 | `settlementDateOf()` 경과 · 미기록 |
| **시스템 현황** | 긴급 N건 | 배치 실패 · 장애 |

⚠️ 네 번째 칸은 **건수가 아니라 시스템 현황**이다. 프로토타입 주석 —
「장애를 문의로 알게 되면 늦다」. 배치 13개 중 실패한 것이 여기 뜬다.

⚠️ **휴면 해제 요청**이 추가돼야 한다 (7-1절). 큐가 5칸이 되거나,
시스템 현황과 묶는다.

## 9-4. 「오늘」 나머지 절

프로토타입 순서 그대로:

| 절 | 골격 |
| --- | --- |
| 회원 현황 | `repeat(3,1fr)` · 칸 사이 `border-right` |
| 트래픽 | `minmax(0,1fr) 420px` — 좌 막대그래프(높이 76px), 우 `1fr 1fr` 4칸 |
| 오늘 오픈 | `repeat(3,1fr)` |
| 오늘 할 일 | `repeat(3,1fr)` |
| 신고 목록 + 우측 | `minmax(0,1fr) 340px` · `align-items:stretch` |

⚠️ 좌우 컬럼은 **바닥선을 맞춘다** — 각 컬럼 `display:flex; flex-direction:column`,
늘어날 카드에 `flex:1; min-height:0`, 내부 스크롤은 `overflow-y:auto`.

## 9-5. 이미 있는 화면은 얹기만

`admin/reports` · `admin/credits` · `admin/credits/policy` · `admin/users` ·
`admin/sanctions` 는 **다시 만들지 않는다.** 셸 안으로 옮기고 「← 뒤로」를 뺀다.

⚠️ `admin/sanctions` 는 프로토타입에서 **신고 화면 안**에 있다.
사이드바에 따로 두지 말고 신고 상세에서 들어가게 한다.
