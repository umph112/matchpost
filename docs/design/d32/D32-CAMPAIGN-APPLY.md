# 0. 무엇이 없나

**캠페인을 등록할 수 있고 검색에 보이는데, 아무도 참여할 수 없습니다.**

| 칸 | 상태 |
| --- | --- |
| 캠페인 등록 (단계 조합 포함) | ✅ `campaigns/new` — `stage_pre_confirm` · `stage_post_edit` 저장 |
| 인플루언서가 검색에서 찾음 | ✅ `influencer/search` — `is_public` + `status='open'` |
| **→ 지원** | ❌ **없음** |
| 광고주 확정 | ❌ 확정할 대상이 안 생김 |
| 딜시트가 정한 단계로 열림 | ❌ 열 딜시트가 없음 |

봇 점검에서 `campaigns` 0행 · `campaign_id` 있는 `proposals` 0행으로 실측됐습니다.
findings 4번 「캠페인 협업 — 만들 수가 없음」이 이것입니다.

## 배선이 어디서 끊기나

```
검색 카드 「대시하기」 → /influencer/messages?receiverId=…     ← campaign_id 를 안 들고 감
                                                              (search/page.tsx:183)

ConfirmDashModal  campaignId 를 받으면 p_kind:'campaign' 으로 넘김   ← 준비돼 있음
DashSendButton:41 campaignId 를 그대로 전달                          ← 준비돼 있음
   ↑
그런데 이 값을 채우는 화면이 하나도 없다
```

`proposals` 를 만드는 네 곳이 전부 `p_campaign_id: null` 로 하드코딩돼 있습니다
(`advertiser/proposals/new:84` 외 3곳).

**즉 그릇은 다 있고 값을 넣는 곳만 없습니다.**

# 1. 인플루언서 — 지원하기

## 1-1. 검색 카드에 버튼

```
src/app/(dashboard)/influencer/search/page.tsx:183
```

지금 「대시하기」 하나뿐입니다. 캠페인 카드에는 **「지원하기」** 가 맞습니다 —
광고주가 이미 조건을 내걸었으니 인플루언서가 제안하는 것이 아니라 참여를 신청하는 것입니다.

| 결과 종류 | 버튼 | 왜 |
| --- | --- | --- |
| 캠페인 카드 | **「지원하기」** | 조건이 이미 정해져 있음 |
| 인플루언서 오픈 (광고주 쪽 검색) | 「대시 보내기」 | 조건을 제안하는 것 |

```
「지원하기」 → ConfirmDashModal 에 campaignId 를 넘긴다
```

`157` 행의 `{/* 신청하기 전에 보여야 의미가 있다 */}` 주석이 이 자리입니다.

## 1-2. 지원 모달에서 받을 것

`ConfirmDashModal` 을 재사용하되, 캠페인 지원일 때는 **날짜 선택이 다릅니다**:

| | 오픈 대시 | 캠페인 지원 |
| --- | --- | --- |
| 날짜 | 광고주가 고름 | **캠페인 기간 안에서 인플루언서가 고름** |
| 페이 | 협의 | 캠페인에 정해진 값 (표시만) |
| 채널 | 협의 | 캠페인이 요구한 채널 |

⚠️ **캠페인 기간(`start_date`~`end_date`) 밖 날짜는 막으세요.** 지금 `ConfirmDashModal` 은
날짜 제한이 없습니다.

⚠️ **크레딧을 깎지 마세요.** 지원은 인플루언서가 하는 것이고, 크레딧은 광고주가 대시를
보낼 때 쓰는 값입니다. `POLICY` 에 「캠페인 지원」 항목이 없는지 확인하고, 없으면 0으로 두세요.

## 1-3. 중복 지원 막기

같은 캠페인에 두 번 지원할 수 없습니다.

```sql
-- 이미 있는지 확인 후 insert (또는 유니크 인덱스)
select 1 from proposals
where campaign_id = :cid and influencer_id = :me
```

이미 지원했으면 버튼이 **「지원함」** 으로 바뀌고 눌리지 않습니다.

⚠️ `0096` 처럼 **DB 에도 못을 박으세요** — 화면만 막으면 두 창으로 뚫립니다.

# 2. 광고주 — 확정

## 2-1. 캠페인 상세에 지원자 목록

```
src/app/(dashboard)/advertiser/campaigns/[id]/page.tsx
```

지금 딜시트만 그립니다. **지원자를 넣는 길이 없습니다.**

딜시트 **위**에 지원자 카드를 두세요:

```
「지원자 N명」 헤더 · 모집 인원 대비 (「3 / 5명」)

행: 아바타 36px + 활동명 + 채널 배지 + 팔로워 + 매치 스코어
    지원 날짜 · 지원 메시지 (한 줄)
    우측: 「프로필」(보조) · 「확정」(검정)
```

**확정하면 그 사람이 딜시트 행으로 내려갑니다.** 지원자 목록에서는 사라집니다.

## 2-2. 모집 인원이 차면

```
모집 인원에 도달하면 「모집 완료」 배지 + 캠페인 status 를 'closed' 로
```

⚠️ **자동으로 닫지 마세요.** 광고주가 「모집 마감」을 누르게 하세요 —
5명 모집인데 6명째가 더 좋을 수도 있습니다. 대신 「N명 확정 · 모집 인원 도달」을 알려주세요.

## 2-3. 확정 = 양쪽 확정

지원은 인플루언서가 이미 「하겠다」고 한 것입니다. 그래서 광고주 확정 하나로 양쪽이 성립합니다.

```
지원 시점    influencer_confirmed = true
광고주 확정  advertiser_confirmed = true  → 협업 성립
```

⚠️ 오픈 대시와 반대입니다 — 그쪽은 광고주가 먼저 보내고 인플루언서가 수락합니다.
**「지원 → 확정」과 「대시 → 수락」이 같은 두 칸을 다른 순서로 채웁니다.**

## 2-4. 반려

```
「확정」 옆에 「반려」 (보조 · 회색)
반려하면 목록에서 사라지고 인플루언서에게 알림
```

⚠️ **반려 사유를 필수로 하지 마세요.** 지원자가 많으면 사유를 다 쓰기 어렵고,
그러면 아무도 반려를 안 눌러 목록이 쌓입니다. 사유는 선택입니다.

인플루언서 알림 문구 — 「아쉽게도 이번 캠페인은 함께하지 못하게 됐어요」
(사유가 있으면 함께 표시)

# 3. 딜시트가 정한 단계로 열려야 한다

확정된 뒤 딜시트가 **캠페인 등록 때 정한 단계**로 열리는지가 이 기능의 마지막 칸입니다.

## 3-1. ⚠️ `computeEnabledStages` 에 「가이드」가 없다

조사에서 확정됐습니다 — `campaignType` · `preConfirm` · `postEdit` **어떤 조합에서도**
「가이드」를 내보내지 않습니다. `ALL_STAGES` 에도 `STAGE_OWNER` 에도 있는데
그 함수만 빠뜨립니다 (`lib/campaign-stages.ts`).

```
현재  협의 · 수락 · 방문 · 원고 · 수정/컨펌 · 게재 · 게재뒤수정 · 정산   (최대 8)
맞음  협의 · 수락 · 가이드 · 방문 · 원고 · 수정/컨펌 · 게재 · 게재뒤수정 · 정산  (최대 9)
```

**진행 중인 건의 단계 배열이 바뀌므로 조심해야 합니다.** 이렇게 하세요:

- 함수를 고쳐 「가이드」를 포함시킨다
- **이미 진행 중인 협업은 현재 단계 인덱스를 보정**한다 (가이드가 끼면 뒤 단계가 한 칸 밀림)
- 또는 「기존 건은 그대로 · 신규만 9단계」로 캠페인에 단계 배열을 저장해둔다

⚠️ 보정 없이 함수만 고치면 **「원고」에 있던 건이 「방문」으로 되돌아갑니다.**
어느 방식으로 갈지 먼저 보고해 주세요.

## 3-2. 확인

캠페인 등록에서 「수정/컨펌 끄기」로 만든 캠페인의 딜시트가
**수정/컨펌 없이 게재뒤수정으로** 이어지는지 확인하세요. 그것이 「등록 때 정한 값이 원본」의 증거입니다.
